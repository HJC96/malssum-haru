- 작성일: 2026-09-26
- 상태: 기존 진도 패널·드래그 정렬·내부 스크롤은 구현 완료; 8절 첫 방문자 빠른 계획 흐름은 계획 추가이며 미구현
- 기준: 사용자의 추가 개선 요청 3건과 후속 정정(진도 기능은 유지하고 자연스럽게 배치). 앞서 구현한 QT/일독 상위 탭과 디자인 위에 적용한다.
- 관련 문서: [PRD](../PRD.md), [작업 목록](../team/TASKS.md), [기존 탭 구현 계획](UI_TABS_QT_PLAN.md)

## 1. 변경할 화면

계획 설정과 진도 기록을 분리해 처음에는 계획을 쉽게 만들고, 필요할 때 진도를 입력하도록 구성한다.

1. 진도 기능은 유지한다. 계획 설정 폼에 펼쳐진 진도 입력을 결과 영역의 접이식 `진도 기록` 패널로 옮긴다. 일정 재배분은 별도의 `남은 일정 조정` 동작으로 정리한다.
2. 선택한 책의 읽는 순서는 드래그로 바꾼다. 각 행의 위로/아래로 이동 버튼은 없앤다.
3. 날짜별 목록과 월간 캘린더를 같은 크기의 결과 박스에 표시한다. 긴 목록은 박스 안에서 스크롤하고 내보내기 버튼은 박스 밖에 둔다.

진도 삭제안은 사용자의 후속 정정으로 철회했다. 전체 진행률·남은 분량·오늘 달성률은 유지하되, 요약과 입력을 필요한 만큼만 보여 준다.

QT 수집 설정과 서버리스/MSA 작업은 이번 계획의 변경 대상이 아니다. 앞선 QT 미표시 진단·실취득 확인 상태는 별도 과제로 남긴다.

## 3. 진도는 요약으로 보여 주고 입력은 필요할 때 열기

### 기본 화면

- 위쪽 계획 설정에는 범위·순서·기간·요일·제외일·배분 방식·계획 이름만 둔다.
- 결과 영역은 `진도 카드 → 목록/캘린더 전환 → 결과 박스 → 내보내기` 순서다.
- 진도 카드에는 전체 진행률, 짧은 진행 막대, 남은 분량과 `진도 기록` 버튼을 둔다. 기록이 있으면 버튼은 `진도 수정`으로 바뀐다.
- 아직 입력하지 않았을 때는 `진도를 기록해 보세요`로 안내한다. 미입력과 사용자가 명시한 읽은 분량 0을 구분하고, 미입력을 실제 0% 진도로 단정하지 않는다.
- 오늘 배정은 항상 확인할 수 있다. 오늘 달성률은 오늘 범위를 입력했을 때만 요약에 추가한다. 전체 목표·읽은 절 수·평균 등 나머지 수치는 `상세 보기` 안에서 확인한다.

### 진도 기록 패널

- `진도 기록`을 누르면 카드 아래에 인라인 패널이 열린다. 기본은 닫힘이며, 열기 버튼에 펼침 상태와 대상 연결을 제공한다.
- 기본 입력은 `여기까지 읽었어요`: 성경 책·장·절을 고른다. `여러 구간을 읽었어요`로 전환하면 기존 개별 범위 입력을 사용할 수 있다.
- 기존의 세 가지 긴 라디오 설명을 항상 나열하지 않는다. 읽은 분량이 0인 경우는 패널 안의 보조 동작 `아직 시작 전이에요`로 명시할 수 있다.
- `오늘 읽은 분량도 입력`은 패널 안의 선택적 펼침 영역이다. 기존 `todayRead`와 누적 범위를 구분하는 계산 규칙은 유지한다. 오늘 입력을 누적 진도에 자동 합치거나 자동 완료 처리하지 않는다.
- `진도 반영`과 `취소`를 제공한다. 입력 중인 초안은 카드/계획에 바로 반영하지 않는다. 유효한 입력을 반영하면 카드를 갱신하고 패널을 닫는다. 취소는 기존 기록과 계획을 유지한다.
- 범위 검증, 중복 범위 합집합, 100% 상한, 목표 밖 범위 오류를 유지한다. 범위/책 순서를 바꾼 뒤 기존 진도가 유효한지도 검사하고 오류를 조용히 지우지 않는다.
- 패널을 닫으면 열었던 버튼으로 포커스를 돌린다. 같은 방문의 서비스 탭 왕복에서는 입력·펼침 상태를 유지한다.

### 남은 일정 조정

- 기존 `오늘 기준으로 남은 범위를 다시 배분` 체크박스를 진도 카드의 보조 버튼 `남은 일정 조정`으로 바꾼다.
- 버튼을 누르면 현재 진도와 오늘 날짜를 기준으로 남은 날짜·하루 평균의 변경 전후를 미리 보여 주고, `이 일정으로 적용`을 눌러 확정한다. 남은 날짜가 없으면 마감일 수정을 안내한다.
- 진도 입력만으로 현재 날짜별 계획표나 오늘 목표의 분모가 바뀌지 않도록 한다. 새 진도를 배정에 반영하는 시점은 일정 조정을 적용할 때다.
- 이를 위해 편집 초안, 반영한 진도, 현재 배정에 사용한 진도/기준일 스냅샷을 UI 상태에서 구분한다. 초기 배정은 읽은 분량 없음 기준이며, 일정 조정 시 최신 진도로 기존 계산 엔진을 호출한다. 일반 계획 조건 변경은 현재 적용된 배정 기준으로 다시 계산한다.
- 오늘 달성률은 항상 화면에 적용된 계획표의 오늘 목표와 비교한다. 미리보기 중에는 기존 목표를 유지하고 확정 시 기준 변경을 알린다.
- 계산 엔진의 진도·재배분 기능, baseline 비교, 관련 테스트를 보존한다. 화면/내보내기/인쇄는 동일한 적용 완료 계획을 사용한다.

### 저장 범위

현재 구현은 입력한 진도를 이 화면에서 계산하는 기능이다. 새로고침·재방문 후 복원하는 저장 기능은 없다. 이번 안도 같은 정책을 유지하고 패널에 `입력한 진도는 현재 화면에서만 유지됩니다`를 한 번 안내한다. 실제 장기 기록·저장 기능 추가는 별도 범위다.

## 4. 책 순서 드래그 정렬

### 사용자 동작

- 각 항목은 `드래그 핸들 / 순번 / 책 이름 / 선택 해제`로 구성한다.
- 마우스는 핸들을 누른 채 이동하고, 터치는 핸들을 길게 눌러 이동한다. 이동 중 항목과 삽입 위치를 구분해 보여 준다.
- 일반 클릭만으로 순서는 바뀌지 않는다. 터치 화면에서 핸들 바깥을 쓸면 페이지가 정상 스크롤돼야 한다.
- 드래그 중에는 임시 순서만 보여 주고, 놓았을 때 `form.bookIds`를 한 번 변경한다. 이동할 때마다 전체 일독 계획을 재계산하지 않는다.
- 취소하거나 유효한 위치 밖에 놓으면 원래 순서를 유지한다. 이동 완료 후 해당 항목에 포커스를 유지한다.
- 책을 새로 선택하면 맨 뒤에 추가한다. 선택 해제는 해당 책만 제거하고 나머지 상대 순서를 보존한다. 빈 목록에는 기존 안내를, 한 권일 때는 정렬할 필요가 없는 상태를 보여 준다.

### 키보드와 구현 경계

- 위/아래 버튼은 화면에서 제거하되 키보드 정렬은 지원한다. 핸들에 포커스 → Space/Enter로 선택 → 위/아래 방향키로 이동 → Space/Enter로 확정, Escape로 취소한다.
- 조작 안내와 이동 결과(예: “요한복음, 3권 중 1번째”)를 한/영으로 제공하고 결과는 live region으로 알린다. 핸들 터치 영역은 최소 44px로 잡는다.
- 새 `BookOrderList.tsx`는 `bookIds`, `onReorder(nextIds)`, `onRemove(bookId)`를 받는다. 책 이름 번역은 기존 i18n을 사용한다.
- 항목 식별자는 배열 인덱스가 아닌 `bookId`를 쓴다. 재정렬 전후 책 집합과 개수는 같아야 한다.
- lead가 구현 시작 시 React 19/TypeScript 7과 호환되는 정렬 도구의 공식 문서·라이선스·마우스/터치/키보드 지원을 확인해 선택한다. 의존성 및 lockfile 수정은 lead만 담당한다. 데스크톱 HTML drag 이벤트만으로 끝내지 않는다.

## 5. 목록과 캘린더의 공통 결과 박스

### 크기와 배치

- `PlanScheduleView.tsx`를 추가하고 보기 선택 아래에 공통 `.plan-view-frame`을 둔다. 목록과 캘린더는 같은 너비·높이·테두리·여백을 사용한다.
- 캘린더의 현재 높이는 고정값이 아니므로 한 달의 실측 높이를 목록에 복사하지 않는다. 두 보기에 공통 높이 토큰을 적용한다.
- 초기 높이안: `--plan-view-height: clamp(24rem, 65dvh, 40rem)`. 두 보기 모두 이 값을 사용하며, 실브라우저 확인 후 조정하더라도 같은 토큰을 유지한다.
- 외곽은 고정 높이의 세로 flex/grid, 내용 영역은 `min-height: 0; overflow-y: auto`로 만든다. 캘린더의 월 이동·주 시작 선택은 박스 상단에 남기고, 월 격자와 날짜 상세는 필요할 때 내부에서 스크롤한다.
- 목록/캘린더를 바꿔도 아래 내보내기 영역의 위치가 크게 이동하지 않아야 한다. 365일 목록을 펼쳐도 페이지가 365개 행 높이만큼 늘어나지 않는다.

### 스크롤과 상태

- 데스크톱 목록의 열 제목은 스크롤 안에서 sticky 처리한다. 모바일은 기존 날짜별 카드 표현을 유지하며 가로 넘침을 점검한다.
- 스크롤 영역에는 접근 가능한 이름과 키보드 포커스, 포커스 표시를 제공한다. 휠/터치/방향키/PageUp/PageDown으로 마지막 날짜까지 볼 수 있어야 한다.
- `scrollbar-gutter: stable` 등으로 스크롤바 때문에 두 보기의 폭이 달라지는 현상을 줄인다. 페이지 스크롤이나 키보드 포커스를 가두지 않는다.
- 같은 계획에서 보기 왕복 시 목록 스크롤과 캘린더의 선택 월·날짜를 유지한다. 공통 wrapper에서 두 뷰를 유지하고 비활성 뷰는 `hidden` 처리하는 방식을 우선한다. 숨은 뷰의 포커스와 접근성 노출을 막는다.
- 계획 기간/범위/순서가 바뀌면 목록은 처음으로, 캘린더는 새 계획의 오늘 또는 첫 달로 재설정한다. 번역만 바뀌면 보기 상태를 유지한다.
- 내보내기와 `PlanPrintSheet`는 스크롤 박스 밖에 유지한다. 화면에서 일부 행만 보여도 Excel/PDF/인쇄는 선택한 출력 범위 전체를 사용한다. 인쇄 CSS는 공통 박스를 숨기고 기존 인쇄 전용 계획표를 출력한다.
- 처음부터 페이지 나누기나 가상 스크롤을 추가하지 않는다. 내부 스크롤과 기존 전체 데이터 모델로 요구를 충족하고 성능 문제가 확인될 때 별도 판단한다.

| schedule-view | 새 `PlanScheduleView.tsx`, `PlanDayList.tsx`, `PlanCalendar.tsx`, `styles/plan.css`, `PlanViews.test.tsx` | 동일 크기 결과 박스와 내부 스크롤, 보기 상태 유지 |
| lead 통합 후 QA | 관련 파일 읽기 검토, `docs/qa/plan-simplification-review.md` | 새 요구 검수, 모바일·인쇄·드래그 실기와 미확인 사항 기록 |

세 구현 담당은 분리된 파일에서 병렬 진행하고, 공유 폼·섹션·번역·의존성 파일은 lead만 수정한다. `PlanSection.test.tsx`, `app/test/planUi.ts`, 기존 noStorage/a11y/export 테스트의 UI 진입 변경도 lead가 통합 단계에 반영한다. QA에서 발견한 결함은 소유 담당에게 돌린다.

PRD의 PLAN01/PLAN05/STAT01과 AC23/AC24/AC26의 진도 기능은 유지하고 진입 위치·반영 시점만 새 UX에 맞춰 구체화한다. AC08의 조건 변경 재계산, AC10의 보기 일치, AC17의 출력 일치와 비저장 조건도 유지한다. 앞서 제안한 진도 제거안을 구현하지 않는다.

## 7. 완료 기준

- P-01: 한/영 모두 초기 계획 설정에 긴 진도 입력이 펼쳐져 있지 않다. 진도 카드에서 입력을 열어 연속/개별 범위와 선택적 오늘 기록을 사용할 수 있고, 미입력과 명시적 0을 구분한다. 취소/반영과 포커스 복귀가 동작한다.
- P-02: 진도 반영은 요약을 갱신하며 적용된 날짜별 배정을 자동 변경하지 않는다. 일정 조정 미리보기 취소는 원복되고 확정하면 최신 미독 범위가 누락·중복 없이 남은 날짜에 배정된다. 오늘 목표 기준과 화면/출력이 일치한다. 기간/요일/제외일·오류·날짜 경계 동작도 유지한다.
- P-03: 실제 마우스·터치 드래그와 키보드 정렬 모두 책 순서를 바꾼다. 취소 시 원복되고 선택 해제 버튼은 드래그를 일으키지 않는다.
- P-04: 순서 변경은 실제 첫 배정 범위와 후속 날짜, 캘린더, Excel/PDF에 동일하게 반영된다. 단순히 화면 행만 바뀌어서는 안 된다.
- P-05: 동일한 뷰포트에서 목록/캘린더 외곽의 너비·높이 차이는 1px 이내다. 1년 목록의 마지막 행을 박스 안에서 확인할 수 있고 내보내기는 박스 밖에 있다.
- P-06: 캘린더 4/5/6주 월, 긴 책 이름·장절, 한/영, 좁은 화면(360px)과 데스크톱, 다크모드, 확대(200%)에서 내용에 접근할 수 있다.
- P-07: QT/일독 왕복과 목록/캘린더 왕복의 상태 정책이 지켜진다. 화면 상태는 새로고침 후 복원하지 않는다.
- P-08: 화면 스크롤 위치와 무관하게 인쇄 미리보기와 내보낸 파일에 전체 선택 출력 범위가 담긴다. QT 탭에서는 숨은 계획표가 인쇄되지 않는다.

관련 기존 테스트를 새 요구에 맞게 수정하고 정렬의 취소/실제 배정 반영 같은 회귀 위험을 검증한다. DOM 단위 테스트만으로 드래그·스크롤 높이·인쇄 성공을 판정하지 않는다. 마지막에 웹 typecheck/test/build와 `git diff --check`를 실행하고, 실제 브라우저 검수 결과를 QA 문서에 남긴다.

## 8. 첫 방문자를 위한 빠른 계획 만들기 추가안 (2026-09-27)

### 현재 진입 장벽

현재 `PlanForm`은 범위, 날짜, 요일, 제외일, 분배 방식 등 여러 설정을 한 화면에 동시에 보여 준다. 기본 계획은 이미 성경 전체·오늘부터 365일·매일 읽기지만, 처음 온 사용자는 각 설정의 의미를 알아야 결과를 얻을 수 있고 `계획 만들기`라는 명확한 시작 동작도 보이지 않는다. 진도 입력은 간소화 계획에 따라 별도 패널로 옮겨졌으므로, 이번 추가안에서는 읽기 계획을 처음 만드는 흐름만 다룬다.

### 제안 사용자 흐름

기본 화면은 가장 흔한 계획을 빠르게 시작할 수 있는 세 가지 선택과 하나의 행동 버튼으로 줄인다.

1. **무엇을 읽을까요?** `성경 전체`를 기본으로 하고 `구약`, `신약`, `직접 고르기`를 함께 제공한다. 직접 고르기를 택할 때만 책 목록과 드래그 순서를 연다.
2. **언제까지 읽을까요?** `30일`, `90일`, `180일`, `1년`, `직접 날짜` 프리셋을 제공한다. 시작일은 오늘로 채우고, 기간 선택 시 종료일을 자동 계산한다. 기존 기본 기간(365일)을 `1년` 프리셋으로 유지한다.
3. **일주일에 며칠 읽을까요?** `매일`, `주 6일`, `주 5일`, `요일 직접 선택`을 제공한다. 기본은 현재 기본값인 매일 읽기다. `요일 직접 선택`을 펼쳤을 때만 7개 요일 토글을 노출한다.
4. **계획 미리보기** 버튼을 누르면 총 장·절 수, 읽는 날짜 수, 하루 평균 분량을 요약하고 결과 목록/캘린더로 이동한다. 버튼은 서버 저장이나 영구 생성을 뜻하지 않고, 현재 화면에서 계산 결과를 확인하는 동작임을 명확히 안내한다.

```text
무엇을 읽을까요?   [성경 전체] [구약] [신약] [직접 고르기]
언제까지 읽을까요? [30일] [90일] [180일] [1년] [직접 날짜]
읽는 요일은요?     [매일] [주 6일] [주 5일] [직접 선택]
                   [계획 미리보기]
계획 요약: 365일 · 매일 읽기 · 하루 평균 약 N절
오늘 읽을 범위 → 날짜별 목록 / 캘린더 → 진도 기록 · 내보내기
```

### 고급 설정과 상태 원칙

- 기본 흐름에는 선택 책 순서, 쉬는 날짜 지정, 장/절 분배, 계획 이름 같은 설정을 노출하지 않는다. `세부 설정` 접이식 영역으로 옮기되 기능은 제거하지 않는다.
- 날짜를 직접 지정하면 시작일·마감일 입력을 펼친다. 제외일은 고급 설정에 두고, 날짜 범위 밖·중복 제외일 오류는 기존 검증을 유지한다.
- 배분 방식은 기본 `절 수 기준(장 끝 우선)`으로 설명하고, `장 수 기준`은 고급 설정에 둔다.
- 계획 미리보기 전에는 결과를 빈 화면으로 두지 않는다. 기본값으로도 미리보기를 만들 수 있고, 설정을 변경한 뒤에는 미리보기 요약이 최신 입력과 일치해야 한다.
- 계산은 기존 `computePlan`/`computeFromForm`을 계속 사용한다. 빠른 설정은 기존 `PlanFormState`의 범위, 날짜, 요일, 제외일, 배분 필드로 변환하는 얇은 입력 계층으로 구현한다.
- 진행률·읽은 범위·남은 일정 재배분은 생성 흐름에 끼워 넣지 않고 현재의 `진도 기록` 및 `남은 일정 조정` 영역에 둔다. 기록을 강요하지 않으며 읽기 계획과 QT 화면 간 데이터 분리 및 비저장 정책도 유지한다.
- 계획 화면 첫 진입 시 짧은 예시 문구로 세 가지 입력을 안내하되, 강제 다단계 wizard는 피한다. 사용자가 한 화면에서 선택을 훑고 바꿀 수 있도록 한다.
- 한/영 지원, 키보드 접근성, 모바일 반응형, 오류 시 입력 보존을 구현 범위에 포함한다.

### 구현과 검수 순서

1. 기본 기간 프리셋 계산과 범위·요일 프리셋 변환 함수를 순수 함수로 만든다. 윤년, 시작일 포함, 제외일과 요일이 겹치는 조건을 테스트한다.
2. `PlanForm`의 기본·고급 영역을 분리하고, 빠른 선택을 기존 폼 상태에 연결한다. 기존 진도 입력 상태와 일독 계산 로직은 수정하지 않는다.
3. `계획 미리보기` 동작, 요약 카드와 결과 섹션 이동을 연결한다. 입력 변경 시 결과 요약이 낡은 값으로 보이지 않게 한다.
4. 선택 기본값, 기간 프리셋, 직접 날짜, 커스텀 책, 고급 분배, 검증 실패, 결과 요약·진도 기록 유지에 대한 웹 테스트를 추가한다.
5. 데스크톱·360px 모바일·키보드만 사용하는 흐름을 실제 브라우저에서 검수하고 작업 결과를 `docs/qa/plan-onboarding-review.md`에 기록한다.

### 완료 기준

- P-09: 첫 화면의 기본 선택만으로 계획 미리보기를 만들 수 있고, 사용자가 별도 설명 없이도 범위·기간·읽는 날을 선택할 수 있다.
- P-10: 30/90/180/365일 프리셋은 시작일을 포함한 올바른 종료일을 계산한다. 윤년·월말·요일·제외일 경계에도 오류나 하루 차이가 없다.
- P-11: 기본 흐름은 네 가지 설정/행동을 중심으로 보이고, 책 세부 선택·요일 토글·제외일·분배 방식·이름은 고급 설정에서 찾을 수 있다.
- P-12: 계획 미리보기 요약과 날짜별 결과·캘린더·내보내기·진도 기록의 계산 값은 기존 계산 엔진을 기준으로 일치한다.
- P-13: 새 흐름도 계획·진도를 서버/브라우저 저장소에 저장하지 않고, QT 탭과 데이터를 공유하지 않는다.
