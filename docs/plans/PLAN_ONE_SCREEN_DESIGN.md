# 일독 계획 한 화면 버튼형 UI 설계

- 작성일: 2026-09-27
- 상태: 구현 시작
- 관련 문서: [PRD](../PRD.md), [일독 계획 간소화 계획](PLAN_SIMPLIFICATION_PLAN.md)

## 목표

일독 계획의 설정과 결과를 한 화면에서 나란히 확인한다. 사용자는 페이지를 길게 내려가며 설정을 찾는 대신 범위·기간·요일 버튼으로 입력 영역을 전환하고, 결과 요약과 일정을 곁에서 확인한다.

## 화면 구성

- 데스크톱은 설정 패널과 결과 패널을 2열로 배치한다.
- 설정 패널 상단에는 `범위`, `기간`, `읽는 요일` 버튼을 두고 선택한 항목의 입력만 보여 준다. 설정 패널 안에서 세부 화면을 세로로 이어 붙이지 않는다.
- 범위는 전체 성경·구약·신약·직접 선택을 제공한다. 직접 선택일 때 책 선택과 기존 순서 정렬을 연다.
- 기간은 30일·90일·180일·1년·직접 날짜 프리셋으로 고른다. 시작일은 오늘을 기본값으로 둔다.
- 읽는 요일은 매일·주 6일·주 5일·요일 직접 선택으로 고른다.
- 제외일, 분배 방식, 계획 이름은 `고급 설정` 버튼에서 연다.
- 결과 패널은 계획 요약, 진도 카드, 목록/캘린더 보기 버튼, 고정 높이 일정 영역, 내보내기 동작 순으로 배치한다.
- 목록/캘린더 버튼은 결과 영역의 보기만 바꾼다. 일정은 공통 크기의 내부 스크롤 영역에서 확인한다.
- 모바일은 2열을 한 열로 바꾸고 `설정`과 `결과` 버튼으로 패널을 전환한다. 선택 상태와 입력은 같은 방문 중 유지한다.

## 동작과 접근성

- 설정 변경은 기존 폼 상태와 계산 엔진을 사용한다. 잘못된 입력은 해당 패널에서 오류를 확인할 수 있게 한다.
- 계획 미리보기, Excel/PDF/인쇄는 기존 기능을 유지하고 전체 계획 범위를 사용한다.
- 진도 기록은 선택 사항이며 요약 카드에서 패널을 연다. 진도 입력만으로 일정을 자동 재배분하지 않는다. 남은 일정 조정은 미리보기와 적용을 거친다.
- QT와 계획 상태를 분리하고 서버·브라우저 저장소에 계획이나 진도를 저장하지 않는다.
- 버튼의 선택 상태, 키보드 포커스, 레이블을 제공한다. 모바일 터치 영역은 충분한 크기를 유지한다.

## 구현 프롬프트

```text
현재 저장소의 PRD와 일독 계획 UI를 확인하고, 일독 계획 화면을 긴 세로 입력 폼에서 한 화면 버튼형 UI로 개선해줘.

목표
- 데스크톱에서 설정 패널과 결과 패널을 한 화면에 나란히 보여 준다.
- 설정은 범위·기간·읽는 요일 버튼으로 전환하고, 선택한 설정 입력만 표시한다.
- 기존 계산, 진도, 남은 일정 조정, 목록/캘린더, Excel/PDF/인쇄 동작을 보존한다.
- 입력과 진도는 서버나 브라우저 저장소에 저장하지 않으며 QT 상태와 공유하지 않는다.

설정 패널
- `범위`, `기간`, `읽는 요일`, `고급 설정` 버튼을 제공한다. 선택 버튼의 입력만 노출하고 나머지 입력은 숨긴다.
- 범위 선택은 성경 전체, 구약, 신약, 직접 선택을 제공한다. 직접 선택에서만 책 목록과 기존 마우스/터치/키보드 책 순서 정렬을 보여 준다.
- 기간은 30일, 90일, 180일, 1년, 직접 날짜를 제공하고 시작일은 오늘을 기본값으로 둔다.
- 읽는 요일은 매일, 주 6일, 주 5일, 요일 직접 선택을 제공한다.
- 제외일, 배분 방식, 계획 이름은 고급 설정 버튼으로 연다.
- 설정 요약을 상단에 간결하게 보여 주고 `계획 미리보기` 버튼을 둔다. 오류가 나면 입력값은 유지하고 관련 오류를 표시한다.

결과 패널
- 계획 요약과 진도 요약을 위에 두고, 목록/캘린더 버튼으로 보기를 전환한다.
- 일정 목록/캘린더는 공통 높이의 결과 박스 안에서 내부 스크롤한다. 내보내기와 인쇄는 전체 계획 데이터를 사용한다.
- 진도 기록 입력은 버튼을 눌렀을 때만 열고, 입력만으로 기존 일정을 바꾸지 않는다. 남은 일정 조정은 미리보기 후 적용한다.

반응형/접근성
- 넓은 화면은 설정과 결과 2열, 모바일은 `설정`/`결과` 버튼으로 한 패널씩 전환한다.
- 선택 상태, 키보드 조작, 포커스 표시, 스크린리더 레이블을 제공한다. 패널 전환 때 입력과 보기 상태를 유지한다.
- 기존 디자인 토큰과 한/영 문자열 체계를 사용한다.

구현 지침
- 먼저 docs/PRD.md, docs/plans/PLAN_SIMPLIFICATION_PLAN.md와 PlanSection.tsx, PlanForm.tsx, PlanSummary.tsx, PlanScheduleView.tsx를 읽는다.
- computePlan/computeFromForm과 기존 폼 상태를 재사용하고 계산 규칙을 중복 구현하지 않는다.
- 관련 UI 검증을 진행하고 변경 파일 및 확인 결과를 요약한다.
```

## 구현 메모

- 기존 `PlanForm`에는 가로 스크롤 단계 패널이 있어 선택하지 않은 입력을 옆으로 넘겨야 한다. 이를 버튼으로 직접 전환하는 패널로 바꾸고, 결과와 같은 화면에서 보이도록 상위 레이아웃을 조정한다.
- 현재 작업 트리에 다른 기능의 수정이 있으므로 관련 파일만 좁게 수정한다.
