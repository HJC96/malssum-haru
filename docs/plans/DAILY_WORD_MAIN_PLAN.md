## 1. 사용자 흐름

상위 탭은 `오늘의 QT`와 `일독 계획`으로 유지한다. QT 탭을 열면 다른 큐티 사이트를 먼저 골라 들어가는 대신 오늘 콘텐츠를 바로 읽는다.

```text
오늘의 QT
  오늘의 말씀 · 2026-09-27
  ┌ 구약 ─ 성경 구절 한 절 ─ 짧은 해설 ┐
  └ 신약 ─ 성경 구절 한 절 ─ 짧은 해설 ┘
  [매일성경 바로가기] [생명의삶 바로가기]
일독 계획
```

- 날짜는 서울 시간 기준으로 하루에 한 번 정하고, 새로고침이나 언어 변경으로 그날 구절이 바뀌지 않는다.
- 두 구절은 각각 하나의 번역본에서 실제로 확인된 한 절을 표시한다. 책·장·절, 번역본, 출처를 바로 가까이 적는다.
- 해설은 각 구절 아래에 제공한다. 2~4문장의 짧은 문맥 설명을 기본으로 하고, 성경 본문 인용과 구별해 표시한다.
- 두 공식 바로가기는 콘텐츠 아래에 동등한 버튼으로 둔다. 기본값은 현재 정해 둔 공식 URL이며, QT 범위 크롤링/API 취득은 새 화면에 필요하지 않다.
- 탭 이름·기존 상위 탭 상태 보존·일독 계획 입력 상태는 유지한다. QT 패널 안의 섹션 제목은 `오늘의 말씀`으로 바꾼다.
- `omalssum-react`에서 참고할 요소는 중앙의 둥근 흰 카드, 옅은 파란색 면, 인디고 버튼, 말씀→해설의 읽기 순서다. 무작위 구절 API, 임시 고정 문장, 외부 이미지 API는 사용하지 않는다.

## 2. 번역본과 본문 사용 선행 조건

이번 변경은 QT 제공처가 게시한 범위를 링크로 안내하던 기존 정책에서, 선택한 번역본의 말씀 두 절을 화면에 표시하는 것으로 범위를 넓힌다. 기존 PRD의 `본문 미표시` 결정은 이 두 절 표시 정책으로 대체한다.

- 화면 기본 언어는 한국어다. 한국어 본문을 사용할 번역본을 출처·이용 조건·재배포 조건까지 검토해 구현 전에 하나 확정한다.
- 현재 조사 문서에 있는 한국어 1910/개역한글 자료는 후보 기록이지, 이 앱에서의 표시·저장·재배포 승인을 뜻하지 않는다. `WEB`은 영어 번역본이며 한국어 본문을 대신하지 않는다.
- 후보의 이용 근거가 화면 표시와 정적 콘텐츠 배포를 명확히 뒷받침하지 않으면, 본문 파일·해설 콘텐츠를 리포지터리나 공개 저장소에 넣지 않는다. `docs/data-sources.md`와 `docs/rights-matrix.md`에 근거·출처·검토일을 남긴 뒤 실제 본문을 채운다.
- 영어 UI를 제공할 경우 한국어 구절을 임의 번역해 성경 본문처럼 보이지 않는다. 영어 번역본과 그 사용 조건을 별도로 선택하거나, 영어 화면에서 한국어 본문을 번역본 라벨과 함께 제공할지 제품 결정을 기록한다.
- 원문 구절은 모델이 생성하지 않는다. 승인된 자료에서 정확히 한 절을 읽어 렌더링하고, 자동 생성 설명이 원문을 다시 출력하거나 긴 문구를 인용하지 않게 한다.
- 본문 자료 선택이 끝나기 전에도 카드·날짜·오류·바로가기 UX는 출처를 표시한 명시적 개발 fixture로 구현할 수 있다. fixture는 실제 콘텐츠, 권리 확인, 정확한 당일 결과로 오인되지 않도록 명확히 분리한다.

## 3. 오늘 콘텐츠 데이터 계약 초안

일자별 응답/파일은 하나의 날짜와 버전으로 두 카드를 함께 제공한다. 한 카드만 갱신돼 두 날짜 콘텐츠가 섞이지 않게 원자적으로 검증한다.

```json
{
  "schemaVersion": "1",
  "date": "2026-09-27",
  "timeZone": "Asia/Seoul",
  "contentVersion": "daily-word-2026-09-27-v1",
  "oldTestament": {
    "reference": { "bookId": "...", "chapter": 1, "verse": 1 },
    "translationId": "...",
    "text": "...",
    "explanation": { "text": "...", "kind": "reviewed" },
    "source": { "name": "...", "url": "..." }
  },
  "newTestament": { "...": "같은 구조" }
}
```

- 두 항목은 각각 구약/신약 책에 속하고 reference는 정확히 한 절이어야 한다.
- `text`는 선택 번역본의 정확한 원문, `explanation`은 별도 작성된 설명이다. 로컬 시편 절 수 테이블처럼 다른 판본의 자료로 절 존재 여부를 추측하지 않는다.
- 날짜·번역본·출처·설명 버전을 추적해 오류가 나면 당일 artifact만 교체할 수 있게 한다.
- 누락·날짜 불일치·잘못된 구절·출처 정보가 있는 경우 검증을 실패시킨다. 전날 구절을 오늘 자료처럼 보여 주지 않고, 본문/해설 실패 상태와 공식 바로가기를 제공한다.
- 두 카드에 사용한 구절과 해설은 내보내기·일독 진도 입력·사용자 개인정보와 무관하다. 개인 기록이나 답변을 API에 보내지 않는다.

## 4. 구현 경로와 서비스 경계

### 첫 출시 데이터 제공

- QT 제공처를 매 요청 때 불러오는 방식 대신, 검토된 날짜별 콘텐츠 artifact를 만들어 정적 호스팅에서 읽는다. 기존 S3/CloudFront 자산 흐름을 먼저 활용해 요청 시 지연과 운영 서비스를 늘리지 않는다.
- 웹에는 `DailyWord` 로더/응답 검증기를 두고 앱은 테스트 가능한 인터페이스에 의존한다. 로컬·테스트는 명시적 fixture, 공개 빌드는 해당 날짜의 실제 artifact만 사용한다.
- 날짜 선택, 구약/신약 분류, 한 절 검증, 번역본·출처 유효성은 생성 단계에서 검사한다. 조회 실패는 카드 영역에서 처리하고 바로가기는 계속 사용할 수 있다.
- 당일 콘텐츠는 미리 준비해 공개한다. 초기에는 전체 365일 본문·해설을 한 번에 생성하거나 게시하지 않고, 검토 가능한 짧은 일정(예: 30일)을 기준으로 공급 운영을 정한다.

### 생성·서버리스·Spring 학습

- 현재 `services/ai`는 WEB 본문을 전제로 한 비활성 골격이다. 이를 그대로 연결해 한국어 본문이나 실시간 AI 설명을 제공한다고 가정하지 않는다.
- 이후 생성 자동화는 API 키·비용 한도·번역본/절 대응·해설 품질 검토 절차가 준비되면 EventBridge 일정 + Lambda 작업 + S3 artifact 저장으로 별도 구성한다. 실패해도 마지막 승인된 자료를 정확한 날짜에만 제공하고, 새 설명을 몰래 대체하지 않는다.
- Spring Cloud는 `daily-content`와 `explanation` 계약, Circuit Breaker, 모의 설명 제공을 로컬 실습으로 이어간다. 대시보드의 정적 콘텐츠 읽기를 위해 Gateway/Eureka를 필수 운영 구성으로 추가하지 않는다.
- 이 일일 선택 기능은 기존 `/api/qt/today`에서 제공처 범위를 조회하는 것과 다른 도메인이다. 기존 QT 어댑터·계약·권리 기록을 새 콘텐츠 데이터의 출처 승인으로 오해하지 않는다.

## 5. 바로가기 동작

- 기존 `officialLinks.ts`의 매일성경·생명의삶 공식 URL과 새 탭/접근성 정책을 재사용한다.
- 버튼은 각 공식 서비스로 직접 연결하고 별도 중간 서버를 거치지 않는다. 날짜 지정 주소가 이미 명시된 서비스만 해당 URL을 사용하고, 오늘 페이지는 버튼의 설명에 날짜가 바뀔 수 있음을 표시한다.
- 바로가기 클릭은 일독 범위나 진도에 반영하지 않는다. 성경 한 절 카드의 출처와 외부 QT 버튼의 목적을 서로 혼동하지 않게 라벨을 분리한다.

## 7. 완료 기준

- D-01: 기본 탭에서 오늘 날짜, 구약 한 절, 신약 한 절 및 각 해설을 바로 읽을 수 있다. 날짜는 서울 기준으로 결정되고 같은 날짜에는 새로고침해도 동일하다.
- D-02: 본문과 해설은 선택 번역본/출처 및 설명 작성 주체가 구분돼 있고, 파일/배포/표시에 대한 근거가 기록돼 있다.
- D-03: 어느 본문도 무작위 외부 API나 모델 출력에서 직접 가져오지 않는다. 구약·신약 classification, single-verse integrity, `date`, `timeZone`, version을 자동 검증한다.
- D-04: 매일성경·생명의삶 버튼은 공식 URL로 직접 열린다. 두 제공처 범위 자동 조회가 없어도 메인 말씀을 볼 수 있다.
- D-05: 자료 누락·오류·시간대 경계가 구체적으로 안내되며 전날 자료를 오늘로 위장하지 않는다. 바로가기는 오류 때도 쓸 수 있다.
- D-06: 한/영 표시, 모바일·데스크톱, 키보드·스크린리더, 다크모드와 출처 표기를 검수하고 결과를 남긴다.
- D-07: QT 탭으로 방문한 페이지와 일독 계획 계산·진도 사이에 데이터가 공유되지 않는다. 새로고침 후 개인 진도는 기존대로 복원되지 않는다.
- D-08: 정적 hosting 단계는 기존 AWS 자산에서 확인하고, 일일 Lambda 자동화나 Spring Cloud를 공개 운영 경로에 포함하려면 비용·장애 경계·보호 키 관리를 별도 검수한다.

### 이번 계획에 포함하지 않는 것

- 매일성경·생명의삶 본문을 자동 크롤링하거나 그 해설을 가져오는 기능.
- 두 절을 합친 본문 전체 검색, 묵상 답변 저장·공유, 사용자별 구절 추천.
- 웹 페이지에 무작위 구절 API나 교체되는 placeholder 본문을 두는 것.
- 사용자 확인 없이 실제 LLM·제3자 API 키를 사용하거나 AWS에 배포하는 일.
- 기존 MSA 실습을 production gateway나 사용자 화면의 필수 경로로 전환하는 것.
