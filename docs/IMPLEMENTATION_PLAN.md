# 말씀하루 구현 인계 계획

- 작성일: 2026-09-24
- 상태: 실행 계획 및 진행 현황 (2026-09-25 갱신)
- 대상: 이 저장소를 이어받아 구현할 개발자 또는 Claude Sonnet 5

이 문서는 [PRD](PRD.md)를 실제 작업으로 나눈 인계서다. 제품 요구사항은 PRD가 우선하며, 이 문서의 기술 선택은 비용과 데이터 사용 조건을 확인하면서 조정할 수 있다. QT·일독·웹·인프라·AI 서비스 골격은 로컬에 구현되어 있다. 실제 성경 본문은 사이트에 표시하지 않고 QT 장절과 공식 링크만 제공한다. AI는 WEB 본문을 내부 입력으로 쓰는 골격만 있으며, 기본 설정에서 실제 생성은 비활성화되어 있다. 전체 상태와 다음 조치는 [인수인계 문서](HANDOFF.md)를 기준으로 한다.

## 1. 이어받자마자 할 일

1. git status를 확인하고 README.md와 docs/PRD.md, 이 문서를 끝까지 읽는다. 현재 PRD와 README에는 기존 스테이징 및 그 이후의 수정이 함께 있으므로 덮어쓰거나 되돌리지 않는다.
2. 이 문서의 “확정·미확정 사항”을 기준으로 구현한다. 미확정 항목은 합리적인 기본값으로 진행하되, 공개 범위나 비용을 바꾸는 결정은 근거와 함께 사용자에게 제시한다.
3. QT·일독·화면·인프라·AI 골격 구현은 완료됐다. 다음은 [docs/HANDOFF.md](HANDOFF.md)와 [docs/team/TASKS.md](team/TASKS.md)의 미완료 QA(M2·AI 골격)를 읽기 전용으로 마무리한다. AWS 배포, 실제 제공처 요청, 실제 LLM 연결은 별도 사용자 지시 전에는 하지 않는다.
4. 각 단계가 끝날 때 실제 완료 항목에 체크하고, 확인한 근거·테스트 결과·남은 문제를 이 문서나 별도 작업 기록에 남긴다. 체크박스를 구현 전에 완료로 표시하지 않는다.

## 2. 변하지 않는 제품 경계

| 항목 | 적용할 기준 |
| --- | --- |
| 첫 QT 제공처 | 매일성경과 생명의삶 두 곳. 365QT는 사용자가 추가 여부를 확정하기 전까지 조사 링크로만 취급 |
| 날짜 | 첫 버전은 제공처 기준 “오늘”만 제공. 과거 날짜를 탐색하는 UI는 만들지 않음 |
| 본문 대체 흐름 | 장절만 확인되면 장절과 해당 날짜의 공식 본문 링크 제공. 장절도 없으면 상태와 공식 링크만 제공. 이전 날짜 자료나 AI 추정값으로 채우지 않음 |
| 본문 표시 | 사이트는 어떤 성경 본문도 표시·보관하지 않는다. QT 장절 범위와 공식 링크만 제공 |
| AI | WEB(World English Bible) 본문은 서버 측 설명 입력으로만 사용하며 화면/API에 반환하지 않는다. 실제 LLM 생성은 권리·비용·품질 검토 전까지 비활성화 |

| 개인 데이터 | 회원가입 없음. 개인 계획·읽은 범위·진도를 서버, localStorage, IndexedDB, sessionStorage 등에 저장하지 않음. 현재 화면 메모리에서 계산하고 파일로 내보냄 |

## 3. 권장 구조와 기술 선택

초기 제안은 브라우저 중심의 일독 기능과 작은 서버리스 QT 백엔드다. 구현을 시작할 때 현재 안정 버전의 호환성을 공식 문서에서 확인해 정확한 버전을 고정한다.

| 부분 | 초기 선택 | 이유와 경계 |
| --- | --- | --- |
| 웹 | React + TypeScript + Vite | 일독 계산·차트·Excel/PDF 생성은 브라우저에서 실행. 개인 입력을 API로 보내지 않음 |
| 성경 구조·계산 | 버전이 붙은 66권 장절 데이터 + 순수 TypeScript 함수 | 화면, 차트, 내보내기가 같은 계산 결과를 사용 |
| QT API·수집 | Java 21, Spring Boot, Spring Cloud Function | Spring 코드를 Lambda에서 실행해 서버리스 경험을 얻음. 의존성 버전은 공식 호환표로 확인 |
| AWS 초안 | 정적 웹 호스팅, API Gateway HTTP API, Lambda, 공통 QT 데이터 저장소, 필요할 때만 일정 실행 | 실제 서비스·리전·과금 방식은 비용표가 통과한 뒤 확정. DB 후보는 DynamoDB |
| 배포 정의 | 한 가지 IaC 도구로 반복 가능한 구성 작성 | 기본 후보는 AWS CDK(TypeScript). 수동 콘솔 설정은 실험 기록에만 사용 |
| AI 확장 | 별도 생성·조회 경계와 영속 결과 저장 | 본문 권한, 품질 기준, 예산 통과 뒤 구현 |
| Spring Cloud MSA 학습 | QT 서비스와 AI 서비스의 독립 계약, 로컬 Spring Cloud Gateway 실험 | 두 서비스가 생긴 뒤 분리의 의미를 검증. 운영 환경의 상시 실행 구성은 비용 검증 후 판단 |

Spring Cloud Function으로 Lambda를 쓰는 일과 Spring Cloud MSA를 운영하는 일은 서로 다른 학습 목표다. 서버리스 공개 구성을 먼저 작게 검증하고, QT·AI의 경계가 드러나면 Gateway, 서비스 간 실패 처리, 설정 분리를 로컬 실험으로 만든다. 이 실험 코드는 실제 서비스 계약과 핵심 로직을 재사용한다.

권장 디렉터리 구조는 다음과 같다. 아직 디렉터리를 미리 만들 필요는 없다.

~~~text
web/                 브라우저 화면, 계산 엔진, 내보내기
services/qt/         QT 조회와 제공처별 어댑터
services/ai/         권한 확보 뒤 AI 결과 조회·생성
infra/               AWS 배포 정의와 비용 관련 설정
labs/spring-cloud/   Gateway 등 MSA 학습 실험
docs/                PRD, 사용 조건, 비용표, 결정 기록
~~~

## 4. 단계별 실행 계획

M0의 권한·비용 확인과 M1의 기술 실험은 함께 진행할 수 있다. 제품 기능의 기본 경로는 M1 → M2 → M3 → M4 → M7이다. M5는 본문 권한과 사람 검토가 준비됐을 때 붙인다. M6은 학습 트랙으로 진행하며 링크 중심 첫 공개를 막지 않는다.

### M0. 데이터·비용·개발 기반 확인

- [ ] 성경 66권 장절 구조 데이터의 출처, 기준 체계, 데이터 버전, 사용 조건을 docs/data-sources.md에 기록한다. 본문 전문 데이터와 장절 구조 데이터를 구분한다.
- [ ] QT 제공처별로 장절 범위 취득, 공식 링크 연결, 본문 웹 표시, 본문 보관, AI 입력, AI 출력 저장·공개를 각각 확인하는 표를 작성한다. “웹에서 보인다”를 재사용 허락으로 취급하지 않는다.
- [ ] 개역개정 권리자와 제공처에 확인해야 할 질문을 정리한다. 실제 문의 메시지 발송은 사용자 지시를 받은 뒤 진행한다.
- [ ] AWS 배포 리전과 예상 트래픽 시나리오를 정하고, 무료 크레딧이 없는 조건까지 포함한 월 비용표를 작성한다. 도메인과 콘텐츠 사용료를 예산에 포함할지 표시한다.
- [ ] Java, Spring Boot, Spring Cloud, Node, 프런트엔드 라이브러리의 현재 호환 버전을 확인하고 잠금 파일과 빌드 파일에 고정한다.
- [ ] README에 로컬 실행·검증 명령을 실제 코드가 생긴 뒤 추가한다.

완료 기준: 출처와 사용 조건의 상태가 “확인됨/문의 중/사용 불가”로 구분되고, 코드가 의존할 데이터 버전 및 비용 가정이 문서에 남아 있다. 권한이 미정이어도 아래의 링크 대체 흐름과 일독 계산 작업은 계속 진행한다.

### M1. QT 장절·공식 링크 연동 실험 — 바로 다음 작업

대상은 [매일성경 오늘의 묵상](https://sum.su.or.kr:8888/bible/today)과 [생명의삶 날짜별 말씀](https://www.duranno.com/qt/view/bible.asp?qtDate=2026-09-24)이다. [365QT](https://www.365qt.com/board/TodayQT)는 후보로 조사하되 첫 버전 제공처에는 넣지 않는다. 2026-09-24 사전 확인에서는 세 링크 모두 접속되었다. 매일성경 화면은 첫 HTML 뒤에 내용을 추가로 불러오는 구조여서 실제 장절 취득 경로를 더 확인해야 한다. 생명의삶 URL의 2026-09-24는 링크 형식을 보여주는 예시 날짜이며, 실행할 때는 제공처 기준 오늘 날짜를 사용한다. 이 관찰은 취득 권한의 확인이 아니다.

- [ ] 각 제공처가 표시하는 날짜 기준, 오늘 장절 범위, 그 범위를 읽을 수 있는 공식 링크를 확인한다. 날짜가 지정된 링크를 우선하고, 없으면 오늘 페이지임을 명시한다.
- [ ] 매일성경의 화면 추가 요청과 생명의삶의 EUC-KR 응답 등 실제 데이터 형식을 로컬에서 조사한다. 제공처마다 어댑터를 분리하고, HTML 구조 변경 시 실패 상태를 반환하게 한다.
- [ ] 자동 취득을 공개해도 되는 조건을 확인한다. 허용 경로가 없으면 해당 제공처는 공식 링크만 표시하는 상태로 남겨 둔다.
- [ ] 내부 공통 모델을 정한다: providerId, providerDate, canonicalPassage 또는 null, displayReference 또는 null, officialUrl, verifiedAt, availabilityStatus, sourceVersion.
- [ ] 최소 API 계약을 작성한다. 예: GET /api/qt/today 응답에 제공처별 상태를 모두 담는다. 한 제공처 실패가 다른 제공처와 일독 화면을 막지 않게 한다.
- [ ] 같은 날짜·같은 제공처의 재수집은 중복을 만들지 않는다. 다른 날짜 자료를 오늘 범위로 반환하지 않는다.
- [ ] 범위만 확인, 범위 확인 실패, 링크 자체 오류의 세 상태를 테스트한다. 테스트에는 성경 본문 전문이나 제공처 해설을 복사하지 않는다.

완료 기준: 로컬에서 두 제공처의 오늘 상태를 같은 JSON 계약으로 확인할 수 있고, 실패 시 유효한 공식 링크 또는 명확한 오류 상태가 나온다. 장절을 입수할 수 없는 제공처가 있어도 그 사실을 기록하고 다음 단계로 간다.

### M2. 일독 계산 엔진과 데이터 검증

- [ ] 책 이름 대신 언어와 무관한 bookId를 사용한다. 장·절 식별자와 장절 데이터 버전을 계획 결과에 포함한다.
- [ ] 전체/구약/신약/선택 책, 사용자 지정 책 순서, 시작일·마감일 포함, 읽는 요일과 제외일을 처리한다.
- [ ] 현재 읽은 범위의 기본 연속 입력과 여러 개별 범위를 모두 지원한다. 겹침은 합집합으로 한 번만 계산하고 목표 밖 범위는 오류로 안내한다.
- [ ] 장 수 균등 배분과 절 수를 고려한 장 끝 우선 배분을 구현한다. 읽기 날짜가 장 수보다 많으면 빈 날을 허용한다.
- [ ] 목표 범위, 읽은 범위, 남은 범위, 날짜별 배정이 동일한 성경 순서와 장절 기준을 사용하도록 한다.
- [ ] 재계산 시 오늘 이후의 읽기 날짜에 현재 화면에서 입력한 미독 범위를 배분하고, 원래 계획과 새 계획을 구분한다.
- [ ] 순수 함수 테스트로 기간 역전, 읽기 날짜 0개, 윤년·월 경계, 겹치는 읽은 범위, 부분 장, 빈 날짜, 모든 범위 소진을 검증한다.
- [ ] 불변식을 검증한다: 날짜별 범위의 합집합은 배정 대상 전체와 같고 날짜 사이의 중복은 없으며 진행률은 0~100%다.

완료 기준: PRD의 AC03~AC06, AC08, AC23~AC24에 해당하는 계산이 UI와 무관한 테스트에서 통과한다. 66권 데이터의 출처와 버전도 재현 가능해야 한다.

### M3. 브라우저 화면, 내보내기, 다국어

- [ ] 오늘 대시보드에 제공처별 날짜·장절·공식 링크·상태를 표시한다. 외부 페이지로 이동하는 버튼은 그 사실을 드러낸다.
- [ ] 계획 입력과 미리보기, 날짜별 목록, 월간 캘린더, 현재 읽은 범위 입력, 남은 장절·진행률 차트를 같은 계산 결과에 연결한다.
- [ ] 오늘 읽은 범위를 별도로 입력하지 않았으면 “미입력”으로 표시한다. 계획상 날짜가 지났다고 읽음 처리하지 않는다.
- [ ] 계획 입력과 결과를 메모리에만 유지한다. 새로고침·재방문 후 복원하지 않으며 브라우저 저장소·URL·분석 이벤트·일반 API 요청에 진도를 넣지 않는다.
- [ ] 실제 .xlsx 파일과 A4 PDF 월간형·목록형, 브라우저 인쇄를 제공한다. 화면과 파일이 동일한 일정 데이터를 공유하고, 긴 범위·한글·영어가 잘리지 않게 한다.
- [x] 한국어·영어 UI를 적용한다. 본문 뷰어는 제공하지 않으며 언어 변경은 현재 계획 조건을 바꾸지 않는다. (기본 구현 완료, 실기 접근성 검수는 M7)
- [ ] 모바일에서 목록을 먼저 읽기 쉽게 만들고 캘린더로 전환할 수 있게 한다. 키보드 조작, 링크 이름, 오류 안내를 확인한다.

완료 기준: PRD의 AC01, AC10, AC17~AC21, AC26을 실제 브라우저에서 확인한다. 새로고침 후 개인 진도가 복원되지 않고, 화면·Excel·PDF의 날짜별 배정이 일치한다.

### M4. AWS 서버리스 배포와 운영 기반

- [ ] 공개 배포 전에 선택한 리전에서 정적 호스팅, API Gateway, Lambda, 데이터 저장, 일정 실행, 로그, 전송량의 월 예상액을 낮음/기준/증가 시나리오로 계산한다.
- [ ] 코드로 배포 가능한 최소 인프라를 만든다. 비밀 키는 저장소와 브라우저 번들에 넣지 않고 서버 측 비밀 관리 방식을 사용한다.
- [ ] QT 공통 데이터만 서버에 저장한다. 개인 계획·진도용 테이블 또는 API는 만들지 않는다.
- [ ] 수집 실패, 제공처 날짜 불일치, 범위 변경, 링크 오류를 관찰할 수 있게 하되 원문 전문과 개인 입력을 일반 로그에 남기지 않는다.
- [ ] 운영자가 제공처 연동을 끌 수 있게 한다. 장애 때 마지막 자료를 “오늘”로 다시 표시하지 않는다.
- [ ] Java Lambda의 첫 요청과 재사용 요청 지연을 각각 측정한다. PRD의 조회 목표를 넘으면 의존성·메모리 설정·SnapStart 같은 대안을 측정해 결정한다.
- [ ] AWS 비용 알림을 설정하고, AI 호출 비용은 애플리케이션의 별도 한도로 제어할 준비를 한다. 예산 알림 자체를 완전한 과금 차단 장치로 간주하지 않는다.
- [ ] 실제 계정에 배포하기 전 IaC 변경 내역과 비용표를 사용자에게 보여준다. 계정·도메인·과금이 필요한 작업의 진행 지시가 없으면 로컬 구현과 배포 정의까지 완료해 둔다.

완료 기준: 샘플 또는 허용된 QT 공통 데이터가 서버리스 경로로 조회되고, 브라우저 계산 기능은 백엔드가 중단돼도 계속 작동한다. 배포 전 추정치를 기록하고 배포 후 실제 청구와 비교한다.

### M5. 권한이 확보된 경우 AI 해설
> 2026-09-24 사용자 결정: QT는 장절과 공식 링크만 표시한다. AI 골격은 T17에서 권고된 WEB(World English Bible)을 내부 입력으로만 사용하며 본문을 출력하지 않는다. 실제 LLM 연결·생성은 비활성화 상태로 둔다.



- [ ] 본문과 앞뒤 문맥의 AI 입력 허용 여부, 생성 결과 저장·공개 조건, 참고 자료, 한국어·영어 검토 담당자를 확정한다. 허용되지 않은 자료는 입력하지 않는다.
- [ ] 서버가 확인한 QT 범위와 고정된 옵션만 AI 요청으로 받는다. 사용자의 임의 프롬프트·모델 설정과 개인 진도는 받지 않는다.
- [ ] 캐시 키에 정규화 범위, 번역·장절 기준, 입력 데이터 버전, 출력 언어, 옵션, 프롬프트·정책 버전, 모델 설정, 참고 자료 버전을 포함한다. QT 제공처명과 날짜를 공통 본문 해설의 기본 키에 넣지 않는다.
- [ ] 같은 키에는 하나의 활성 생성 작업만 허용한다. 결과 상태는 미생성/생성 중/제공 가능/실패/검토 중으로 관리하고, 실패 결과를 정상 콘텐츠로 저장하지 않는다.
- [ ] 예산 부족·호출 제한·LLM 장애 때 신규 생성만 멈춘다. 계속 제공할 권한이 있는 기존 결과와 QT 공식 링크, 일독 계산은 유지한다.
- [ ] 근거 구절의 형식·범위와 출력 필드를 검사하고, 대표 본문의 사실성·해석 차이·한영 품질을 사람이 검토한다.
- [ ] 신고·숨김·리비전 교체를 구현하고 늦게 끝난 이전 생성 작업이 승인된 결과를 덮어쓰지 못하게 한다.

완료 기준: PRD의 AC12~AC16, AC22, AC25를 통과하고 사람 검토와 권한 확인이 끝난 범위만 공개한다. 권한이나 품질 검토가 끝나지 않으면 AI는 비공개로 두고 앞 단계의 기능을 출시할 수 있다.

### M6. Spring Cloud MSA 학습과 확장 판단

- [ ] QT 조회·수집과 AI 조회·생성의 계약과 데이터 소유권을 분리한다. 양쪽이 같은 DB 내부 구조에 직접 의존하지 않게 한다.
- [ ] labs/spring-cloud에서 Spring Cloud Gateway로 두 서비스의 라우팅을 만들고, AI 서비스 중단 시 QT 링크 응답이 유지되는 상황을 재현한다. 실제 AI 자료 권한이 없으면 모의 응답으로 실험한다.
- [ ] 로컬 실습에서 Spring Cloud Config로 두 서비스의 설정을 분리하고 Eureka 서비스 검색을 붙여 정적 주소와 비교한다. Spring Cloud CircuitBreaker로 AI 호출 실패 시 QT 링크가 유지되는 대체 응답을 검증한다.
- [ ] 메시지 큐 같은 추가 구성은 실제 비동기 생성 요구나 별도 학습 목표가 있을 때 도입한다.
- [ ] 로컬 실험의 배포 단위·장애 경계·비용을 기록하고, 공개 AWS 구성으로 옮길 가치가 있는 부분만 선택한다.

완료 기준: QT와 AI 또는 모의 AI 서비스가 독립적으로 빌드·실행·중단될 수 있고, 한쪽 장애의 사용자 영향이 문서와 테스트로 확인된다. 상시 구동하는 MSA 인프라를 월 10,000원 계획에 자동으로 포함하지 않는다.

## 5. 비용표에 반드시 넣을 변수

AWS 가격과 무료 제공 범위는 배포 시점의 공식 페이지에서 다시 확인한다. 세금과 환율도 별도로 계산한다.

| 구분 | 측정하거나 가정할 값 |
| --- | --- |
| 사용자·트래픽 | 일 방문 수, 방문당 QT 조회 횟수, 피크 시간 요청, 정적 파일 전송량 |
| QT 수집 | 제공처별 하루 확인 횟수, 재시도 횟수, 저장 항목 수와 크기 |
| API·실행 | API 요청 수, Lambda 메모리·평균 실행 시간·콜드 스타트, 로그량 |
| 저장 | QT 항목 읽기/쓰기, AI 콘텐츠 읽기/쓰기, 저장 크기와 보관 기간 |
| AI | 하루 새로운 본문·언어 조합 수, 결과 재사용률, 입력·출력 토큰, 실패 재시도 |
| 기타 | 도메인, 콘텐츠 이용료, 모니터링, 세금, 환율, 무료 크레딧 종료 |

최소한 작은 사용량, 예상 사용량, 공개 직후 급증의 세 시나리오를 만든다. 월 10,000원 안에 들어오지 않으면 신규 AI 생성 한도, 캐시 재사용, 요청 빈도, 인프라 선택을 조정하고 결과를 다시 계산한다. AWS Budgets 알림과 애플리케이션의 AI 생성 차단은 별개로 구현한다.
