# QT 통합 대시보드와 성경 일독 계획 서비스 PRD

버전: 0.9<br>
작성일: 2026년 9월 22일  
수정일: 2026년 9월 26일<br>
상태: 제품 요구사항 초안  
대상: 기획, 디자인, 개발 담당자

여러 QT 서비스의 오늘 읽기 범위를 확인하고, AI의 도움으로 본문을 이해하며, 개인 일정에 맞는 성경 일독 계획을 만들고 관리하는 웹서비스를 개발한다. QT와 일독 계획은 하나의 대시보드에서 제공한다. 회원가입과 로그인 없이 이용하며, 개인 읽기 진도는 서버나 브라우저에 저장하지 않는다.

이 문서는 기능 범위, 계산 규칙, AI 생성 결과의 재사용 방식, 화면 구성, 출시 검수 기준을 정의한다. 제품명, 데이터 제공 계약, 기술 스택, 개발 일정은 추후 결정한다.

## 1 제품 방향과 결정 사항

### 확정한 요구사항

- 최초 QT 연동 대상은 생명의삶과 매일성경 두 곳으로 확정한다. 첫 버전은 오늘 본문만 제공하며 과거 날짜 탐색은 제외한다.
- 현재 읽은 분량은 연속 범위와 여러 개별 범위 입력을 모두 지원한다. 연속 범위 입력을 기본으로 한다.
- AI 생성 예산이 부족하면 신규 생성을 중단하고 계속 제공할 권한이 있는 기존 해설, QT 장절·공식 링크와 일독 계산은 계속 제공한다.
- (이전 범위, 2026-09-26 최신 계획으로 일부 대체) 제공처 QT 본문 전문은 표시하지 않는다. 오늘의 메인 콘텐츠 두 절의 번역본 표시 정책은 아래 최신 결정을 따른다.
- AI는 본문 요약, 앞뒤 문맥, 주요 구절 설명과 묵상 질문을 제공한다. 질문에 대한 사용자 답변은 작성하거나 저장하지 않는다.
- 수익화를 계획하지 않으며 무료로 운영한다.
- AWS와 LLM을 합친 월 운영비 목표 상한은 10,000원이다. 이 예산으로 운영 가능한지는 예상 사용량과 실제 요금 검토 후 확인한다.
- 서비스 공개와 Spring 및 AWS 학습을 함께 추구하되, 운영 구조는 단순하게 유지한다.
- 일독 분량 배분은 장 수 기준과 절 수 기준을 모두 제공한다. 기본값은 절 수를 고려해 배분하되 장 끝에서 마치는 방식이다.
- 배포 플랫폼은 AWS로 확정한다. EC2, 서버리스 등 구체적인 실행 방식은 추후 결정한다.
- QT 장절 범위에 대해 이용 조건과 절 번호 대응이 확인된 공개 번역본을 입력으로 AI 설명을 생성하고, 같은 조건의 결과를 저장해 재사용한다. 출력에는 성경 본문을 인용하지 않는다.
- 일독 대상은 개신교 성경 66권으로 확정한다.
- 개인 진도는 저장하지 않는다. 진도 이력, 자동 복원, 백업과 동기화를 제공하지 않는다.
- AI 해설은 본문과 앞뒤 문맥을 중심으로 설명하며 해석이 갈리면 견해 차이를 표시한다.
- 시작일과 마감일을 정하면 성경 읽기 분량을 계산한다.
- 시작일과 마감일, 읽을 목표 범위와 현재 읽은 분량을 입력받아 날짜별 배정, 남은 장절 수, 현재 진행률과 차트를 제공한다. 입력과 결과는 현재 화면에서 계산하며 다음 방문까지 저장하지 않는다.
- 캘린더에서 날짜별 읽기 계획을 확인한다.
- 계획을 Excel로 내보내고, 문서로 출력할 수 있게 한다.
- 한국어와 영어를 지원한다.
- 회원가입, 로그인, 회원 프로필, 묵상 공유와 커뮤니티 기능은 제공하지 않는다.
- **QT와 일독 계획은 독립된 기능이다. QT 열람을 일독 분량에서 차감하거나 일독 진도에 반영하지 않는다.**

### 2026-09-24 범위 결정 (이전 결정; 2026-09-26 오늘의 말씀 범위에서 일부 대체)

- QT는 제공처의 **오늘 장절 범위 표기와 공식 링크**만 제공한다. 어떤 번역본의 성경 본문도 사이트에 표시하거나 보관하지 않는다. 사용자는 제공처 링크를 통해 본문을 읽는다.
- AI 요약·설명의 입력은 개역개정이 아니라 WEB(World English Bible)로 정했다. WEB 본문은 AI 입력으로만 사용하고 화면에 표시하지 않는다. 실제 LLM 연결·생성은 모델, API 키, 비용 상한과 품질 검토를 정하기 전까지 비활성화한다.
- AI는 WEB 본문의 구절 원문을 인용하지 않고 `장:절` 참조와 설명만 반환한다. QT 범위(제공처가 표시한 장절)와 WEB의 절 대응이 검증되지 않은 범위는 생성하지 않는다. 계약은 [docs/contracts/ai-explain.md](contracts/ai-explain.md).
- 제공처(성서유니온·두란노)에 보내는 자동 취득 문의는 사용자가 직접 써 본 뒤 계속 사용하기로 정할 때 진행한다. 그 전에는 발송하지 않는다. 사용자가 먼저 혼자 쓰는 **비공개 시험 운영** 동안에는 배포본의 자동 취득을 켜 두되, 취득은 하루 소수 회의 예약 수집으로만 하고(방문자 요청이 제공처로 전달되지 않는다), 검색 엔진에 노출하지 않으며, 제공처 허용 여부는 여전히 미확인임을 문서에 남긴다. 일반 공개 전에는 제공처 회신 또는 사용자의 별도 결정으로 자동 취득 여부를 다시 정한다.

- 기본 UI와 날짜별 정적 artifact 흐름은 구현되었으며 현재 자료는 하루치다. 다음 단계인 후보 풀 무작위 추출은 아직 구현되지 않았다. UX 설명과 후속 구현 단계는 [오늘의 말씀 메인 계획](plans/DAILY_WORD_MAIN_PLAN.md)의 8절을 따른다.

### 2026-09-27 첫 사용자 계획 생성 및 말씀 선택 원리 계획 추가

- 일독 계획의 기본 진입을 범위·기간·읽는 요일 중심의 빠른 설정으로 단순화하고, 직접 책 선택·제외일·분배 방식 등은 고급 설정에 접는 계획을 추가했다. 현재의 진도 기록, 남은 일정 조정, 개인정보 비저장 정책은 유지한다.
- 오늘의 QT 카드 한쪽 하단에 정보 버튼을 두고, 실제 활성 후보 풀에서 구약/신약을 균등 추출하는 원리를 hover/focus/tap으로 설명한다. 현재 날짜별 자료는 수동으로 준비한 정적 artifact이며 무작위 선택은 아직 작동하지 않으므로, 설명 UI는 추출기가 실제 배포될 때 함께 출시한다.
- 설명 예시의 `1/1,000`, `1/2,000`은 각 성경 전체 절 수가 아니라 검토·승인된 선택 후보가 각각 그 수일 때의 확률이다. 풀 크기 검증, 권리 확인, 날짜 고정 seed 기반 정적 artifact 생성, 중복 허용 정책과 QA를 [일독 계획 개선안](plans/PLAN_SIMPLIFICATION_PLAN.md) 및 [오늘의 말씀 메인 계획](plans/DAILY_WORD_MAIN_PLAN.md)에 명시했다.

## 2 해결하려는 문제와 대상 사용자

여러 QT를 확인하는 사용자는 서비스마다 페이지를 찾아가야 한다. 일독을 계획하는 사용자는 자신의 시작일과 마감일에 맞는 분량을 직접 계산하고, 며칠 읽지 못하면 계획을 다시 조정해야 한다. 장 수만 동일하게 나누면 날짜별 실제 분량이 달라질 수 있고, 계획표를 출력하거나 Excel로 관리하려는 사용자에게는 내보내기 기능도 필요하다.

이러한 불편은 현재 제품 가설이다. 인터뷰나 사용성 검증을 통해 실제 우선순위를 확인한다.

| 사용자 | 이루려는 일 | 주요 기능 |
| --- | --- | --- |
| 매일 QT를 하는 개인 | 오늘 본문을 찾고 내용을 이해한다 | QT 모아보기, 공식 링크, AI 요약과 설명 |
| 일독을 시작하는 개인 | 내 일정에 맞는 읽기 계획을 만든다 | 기간과 요일 설정, 분량 계산, 캘린더 |
| 일정을 조정하는 개인 | 변경된 기간과 읽을 범위로 계획을 다시 만든다 | 조건 변경, 일정 재계산 |
| 계획표를 출력하는 개인 | 화면 밖에서도 계획을 확인한다 | Excel, PDF, 인쇄 |

소그룹 공동 관리와 교회 운영자 기능은 초기 대상에서 제외한다. 개인용 계획표를 공동체에서 배포하는 것은 가능하지만, 구성원 진도를 관리하는 기능은 현재 제품 범위에 포함하지 않는다.

## 3 목표와 기능 범위

제품의 목표는 오늘 구약·신약 말씀과 해설을 읽고 필요하면 공식 QT 사이트로 이동하며, 별도로 일독 계획을 만들고 출력·재계산하도록 돕는 것이다. AI는 본문 이해를 돕는 보조 기능으로 제공한다.

P0는 첫 출시 후보, P1은 후속 기능이다. 우선순위는 이 초안의 제안이며, 데이터 사용 권한 확보 여부에 따라 연동 가능한 서비스와 번역본이 달라질 수 있다.

4. Excel 또는 PDF를 새로 내려받는다. 기존 읽기 이력은 자동으로 불러오지 않는다.

## 5 QT 요구사항

### QT01 오늘 범위와 공식 링크

- 서비스명, 제공처 기준 날짜, 성경 책과 장절, 공식 URL을 표시한다.
- 사용자는 즐겨찾는 서비스를 선택하고 표시 순서를 바꿀 수 있다.
- 일별 범위는 이용 가능한 공식 데이터 또는 사용 권한이 확인된 경로로 확보한다.
- 장절 범위는 확인되지만 본문을 가져올 수 없거나 표시 조건이 확인되지 않은 경우, 장절 범위만 표시하고 해당 날짜의 공식 본문 페이지로 연결한다. 공식 페이지로 이동한다는 점을 버튼에 명확히 표시한다.
- 범위를 확보하지 못했을 때는 해당 상태와 공식 페이지 연결만 제공한다. 이전 날짜의 범위를 오늘 데이터로 표시하거나 AI로 추정하지 않는다.
- 제공처가 한국 날짜를 기준으로 운영하면 그 기준을 표시한다. 사용자의 현지 날짜와 다를 수 있으며, 날짜를 임의로 바꿔서 같은 본문을 오늘 자료로 취급하지 않는다.

### QT04 본문 비표시와 콘텐츠 이용 조건

- 첫 버전은 개역개정을 포함한 성경 본문 전문을 웹 화면, API 응답, 로그에 표시하거나 저장하지 않는다. QT 장절 범위와 공식 링크만 제공한다.
- AI 입력은 WEB(World English Bible)로 제한한다. WEB 본문은 서버에서 설명 생성에만 사용하고 사용자에게 표시하거나 응답에 포함하지 않는다. 실제 LLM 연결 전 데이터 이용 조건과 외부 모델의 데이터 처리 조건을 확인한다.
- 일독 기능은 읽기 계획과 배정 범위를 제공하며, 전체 성경을 읽는 본문 뷰어를 추가하지 않는다.
- 장절 범위가 확인되면 그 범위와 공식 링크를 제공한다. 장절 범위도 확인되지 않으면 추정하지 않고 상태와 공식 링크만 제공한다.
- QT 장절과 WEB 절 번호의 대응을 검증하지 못했거나 필요한 본문·문맥이 없으면 신규 AI 해설을 생성하지 않는다. 기존 결과도 계속 제공할 수 있는 조건을 확인한다.
- WEB 입력, 참조 자료, 생성 결과의 저장 및 제공 조건을 각각 확인한다. 웹에서 볼 수 있다는 사실만으로 AI 입력과 재배포가 허용된 것으로 판단하지 않는다.
- 제공처의 해설과 자체 AI 해설을 화면에서 구분하며, AI 해설을 제공처가 작성하거나 승인한 콘텐츠처럼 표시하지 않는다.

## 6 AI 요약과 해설 요구사항

### AI01 제공할 내용

AI는 지정한 본문 범위에 대해 다음 내용을 생성한다. 한국어와 영어 결과를 각각 지원하고, 사용자는 요약만 보거나 설명을 펼쳐 볼 수 있다.

| 구성 | 제공할 내용 | 검증 기준 |
| --- | --- | --- |
| 요약 | 본문에서 일어나는 일과 핵심 내용을 짧게 정리 | 본문에 없는 사건을 추가하지 않음 |
| 문맥 | 앞뒤 내용과 해당 본문의 관계 | 주어진 주변 본문 또는 확인된 자료에 근거 |
| 핵심 설명 | 이해하기 어려운 표현과 주요 의미 | 설명에 근거 장절을 연결 |
| 묵상 질문 | 사용자가 스스로 생각할 수 있는 질문 | 개인에 대한 예언이나 평가로 제시하지 않음 |

묵상 질문은 읽기 전용이며, 답변 입력과 저장은 제공하지 않는다.

AI가 생성했다는 표시, 생성 결과의 수정일, 오류 신고 경로를 제공한다. 참고 자료가 없는 역사적 배경은 확정 사실로 단정하지 않으며, 해설은 본문과 앞뒤 문맥을 중심으로 작성한다. 해석이 갈리는 내용은 확인된 주요 견해와 차이를 구분해 표시하고, 특정 견해를 유일한 사실처럼 단정하지 않는다. 확인할 수 없는 견해는 지어내지 않고 불확실성을 밝힌다. 참고 자료 목록과 검토 담당자는 추후 결정한다.

### AI02 입력과 품질 관리

- 본문 범위 문자열만으로 생성하지 않고, 허용된 정확한 본문 데이터와 필요한 주변 문맥을 제공한다.
- 번역본과 장절 기준을 명시한다. 입력 데이터가 없거나 권한을 확인하지 못한 경우 생성하지 않는다.
- 출력 형식, 필수 항목, 근거 장절의 유효성을 검사한다. 근거 구절이 실제 주장까지 뒷받침하는지는 별도의 내용 검토 대상이다.
- 첫 출시 전에 대표 본문을 선정해 요약 정확성, 문맥 설명, 해석 표현, 한국어와 영어 품질을 사람이 검토한다. 검토 담당자와 표본 범위는 출시 전에 정한다.
- 심각한 사실 오류나 잘못된 인용이 신고되면 해당 결과의 제공을 중단하고 검토할 수 있어야 한다.

### AI03 공통 결과 저장과 캐싱

같은 조건의 요약과 설명은 여러 사용자가 함께 재사용한다. 생성 결과를 DB에 보관하고, 필요하면 조회 속도를 위한 별도 캐시를 둔다. 메모리 캐시가 사라져도 승인된 기존 결과를 다시 사용할 수 있어야 한다.

논리적인 재사용 키에는 다음 요소를 포함한다.

| 요소 | 이유 |
| --- | --- |
| 정규화한 본문 범위 | 표기 방식이 달라도 같은 범위를 식별 |
| 번역본과 장절 기준 | 다른 번역과 절 구분의 결과가 섞이지 않도록 구분 |
| 본문과 주변 문맥 데이터 버전 또는 해시 | 입력 내용의 수정 반영 |
| 출력 언어 | 한국어와 영어 결과 구분 |
| 콘텐츠 유형과 길이 등 생성 옵션 | 짧은 요약과 상세 설명 구분 |
| 프롬프트와 해설 정책 버전 | 설명 방식과 품질 기준 변경 반영 |
| 모델과 생성 설정 버전 | 생성 조건 변경을 추적 |
| 참고 자료 버전 | 참조 자료가 변경되면 새 결과 생성 |

날짜, 브라우저 식별자, QT 서비스명은 공통 본문 해설의 기본 키에 넣지 않는다. 여러 제공처에서 같은 본문을 다루더라도 입력 조건이 같으면 결과를 공유한다. 특정 제공처의 콘텐츠나 개인 문맥을 입력하는 기능을 추가한다면 별도의 권한 및 재사용 범위로 분리해야 한다.

이 기능의 캐싱은 LLM 공급자의 프롬프트 캐시와 별도로, 서비스가 완성된 생성 결과를 저장하고 재사용하는 것을 의미한다.

### AI04 생성과 실패 처리

1. 요청 조건에 맞는 유효한 저장 결과가 있으면 반환한다.
2. 없으면 해당 키의 생성 작업이 진행 중인지 확인한다.
3. 동일 키에는 하나의 활성 생성 작업만 허용하고 나머지 요청은 그 결과를 기다리거나 생성 중 상태를 받는다.
4. 생성과 검증이 성공하면 결과를 저장하고 제공 가능한 상태로 전환한다.
5. 실패하면 오류 상태와 다시 시도 경로를 제공한다. 실패 내용을 정상 콘텐츠처럼 저장하지 않는다.

생성 상태는 미생성, 생성 중, 제공 가능, 실패, 검토 중으로 구분한다. 호출 제한과 재시도 횟수, 작업 시간 제한을 설정하고 장애 시 중복 생성이 폭증하지 않도록 한다. AI가 실패해도 공식 QT 링크와 일독 기능은 동작해야 한다.

첫 출시는 요청 시 생성과 재사용으로 시작하고, 반복 사용량이 확인되면 오늘의 QT 범위를 미리 생성하는 작업을 추가할 수 있다. 공개 요청은 서버가 확인한 QT 범위와 허용된 생성 옵션으로 제한한다. 임의 프롬프트와 모델 설정은 받지 않으며, 요청 빈도 제한과 전체 호출 예산으로 익명 요청의 과도한 생성을 제어한다.

### AI05 수정과 캐시 무효화

- 운영자는 오류가 있는 결과를 숨기거나 수정 또는 재생성할 수 있다.
- 수정된 결과는 새 리비전으로 보관하고 활성 결과를 교체한다.
- 교체 또는 제공 중단 시 관련 캐시를 함께 무효화한다.
- 늦게 도착한 이전 생성 작업이 수정된 결과를 덮어쓰지 못하게 한다.
- 권한 철회나 사용 조건 변경 시 DB와 캐시에 남은 결과의 계속 제공 여부를 점검하고 필요한 조치를 한다.
- 단순 시간 만료만으로 오류 수정이나 버전 변경을 처리하지 않는다.

## 7 일독 계획과 분량 계산 요구사항

### PLAN01 계획 입력

필수 입력은 전체 목표 범위, 시작일, 마감일, 읽는 요일이다. 현재 읽은 범위를 입력할 수 있으며 처음 시작하는 경우 0으로 계산한다. 제외할 날짜와 배분 방식을 선택할 수 있다. 현재 읽은 범위는 이번 입력값으로 계산하며 이전 방문의 기록이나 QT 열람 이력을 가져오지 않는다. 기본 입력 방식은 목표 범위의 시작부터 마지막으로 읽은 장절까지의 연속 범위다. 건너뛰어 읽은 경우 여러 책의 개별 읽은 범위를 입력하는 방식으로 전환할 수 있다. 두 방식 모두 지원하며 중복 범위는 한 번만 계산한다.

- 읽을 범위는 전체, 구약, 신약, 선택한 책을 지원한다.
- 시작일과 마감일은 모두 포함한다.
- 선택한 요일에 해당하는 날짜 중 제외일을 뺀 날짜를 실제 읽기 날짜로 사용한다.
- 시작일이 마감일보다 늦거나, 읽기 날짜가 0개이거나, 범위가 비어 있으면 계산을 차단하고 이유를 안내한다.
- 계획을 생성할 때 장절 기준과 데이터 버전을 고정한다.

### PLAN02 분량 배분

두 가지 배분 방식을 제공하는 것으로 확정한다. 첫 선택값은 절 수를 고려한 배분이며, 장 끝에서 마치는 것을 기본으로 한다.

| 방식 | 배분 규칙 | 표시할 설명 |
| --- | --- | --- |
| 장 수 기준 | 남은 장 수를 읽기 날짜에 가능한 한 고르게 배분 | 장마다 실제 분량은 다를 수 있음 |
| 절 수를 고려한 배분 | 남은 절 수를 날짜별로 비슷하게 나누되 장 끝을 우선 | 절 수가 읽는 시간을 정확히 나타내지는 않음 |

장 중간을 읽기 범위의 시작이나 끝으로 지정하는 기능을 제공할 경우 해당 범위를 배분 단위로 취급한다. 실제 읽음 여부를 추정하지 않는다. 기본 배분은 장 끝에서 마친다. 장 중간 분할 옵션의 제공 여부는 추후 결정한다.

장의 순서와 사용자 지정 책 순서를 유지하고, 남은 범위가 빠지거나 날짜 사이에 중복 배정되지 않도록 한다. 장 수보다 읽기 날짜가 많으면 일부 날짜를 빈 일정으로 두며, 이를 미완료로 표시하지 않는다. 미리보기에는 실제 배정된 날짜별 범위를 보여준다.

### PLAN03 계산 규칙

| 계산값 | 규칙 |
| --- | --- |
| 계획 절 수 | 선택한 범위에 속한 유효한 절 식별자의 개수 |
| 계획 장 수 | 선택한 범위에 포함된 장 수 |
| 읽기 날짜 수 | 양 끝 날짜를 포함한 기간에서 요일과 제외일 조건을 반영한 날짜 수 |
| 평균 하루 절 수 | 계획 절 수를 읽기 날짜 수로 나눈 값 |
| 날짜별 배정 분량 | 선택한 배분 방식으로 나눈 장절 범위 |

날짜별 범위를 합하면 선택한 전체 범위와 일치해야 한다. 정수 절 배분의 나머지도 일정에 반영한다. 계획상 날짜가 지났다는 이유만으로 실제 읽은 분량으로 계산하지 않는다.

### PLAN05 일정 재계산

- 사용자는 전체 목표 범위와 현재 읽은 범위, 시작일, 마감일, 요일을 직접 수정하고 계획을 다시 계산한다.
- 재계산 전후의 일정을 현재 화면에서 확인할 수 있게 한다.
- 사용자가 이번 화면에서 입력한 읽은 범위만 제외해 남은 분량을 계산한다. 과거 계획과 읽기 이력은 보관하지 않는다.
- 오늘을 기준으로 남아 있는 읽기 날짜에 미독 범위를 재배분한다. 시작일이 미래면 시작일부터 계산한다. 남은 날짜가 0인데 미독 범위가 있으면 마감일 변경을 안내한다. 현재 시점의 재계산임을 표시하고 최초 계획과 구분한다.

### PLAN06 계획 변경 경계

- 현재 화면에서 언어를 변경해도 입력 범위와 계산 결과를 임의로 바꾸지 않는다.
- 장절 기준이나 목표 범위를 바꾸면 새 조건으로 재계산한다.
- 개인 계획을 다시 열기 위한 자동 저장이나 복원은 초기 범위에서 제외한다. 계획표 파일 내보내기는 유지한다.

## 8 캘린더와 진행률 처리

### CAL01 캘린더와 목록

- 월간 캘린더와 날짜별 목록에서 같은 계획을 보여준다.
- 각 날짜에 읽을 범위와 쉬는 날을 표시한다. 실제 완료 상태는 추정하지 않는다.
- 날짜 선택 시 배정 범위를 확인할 수 있다.
- 이전 달, 다음 달, 오늘로 이동을 제공한다.
- 개인 진도를 저장하는 체크 기능은 제공하지 않는다. 출력된 계획표의 빈 체크 칸은 유지할 수 있다.

### STAT01 현재 진도 계산과 차트

진도 계산은 확정 기능이며, 저장하지 않는 것은 입력값과 계산 결과의 재방문 보관이다. 현재 화면에서는 입력을 유지하고 수정할 때마다 결과를 계산한다.

| 지표 | 계산 기준 |
| --- | --- |
| 현재 읽은 절 수 | 목표 범위 안에서 사용자가 입력한 읽은 절의 중복 없는 개수 |
| 남은 절 수 | 전체 목표 절 수에서 현재 읽은 절 수를 뺀 값 |
| 전체 진행률 | 현재 읽은 절 수를 전체 목표 절 수로 나눈 비율 |
| 남은 장 수 | 목표 범위 안에서 아직 전부 읽지 않은 장 수. 부분 읽은 장 포함 |
| 오늘 목표 달성률 | 현재 화면에서 정한 오늘 배정 범위 중 오늘 읽었다고 입력한 범위의 비율 |
| 남은 하루 평균 분량 | 남은 절 수를 남아 있는 읽기 날짜 수로 나눈 값 |

전체 진행률과 남은 분량을 차트와 숫자로 표시한다. 오늘 달성률은 오늘 읽은 범위를 별도로 입력했을 때 계산한다. 입력이 없으면 미입력으로 표시하며, 날짜가 지났다는 이유로 실제 읽은 것으로 취급하지 않는다.

오늘 목표를 재계산으로 바꾸는 경우 기준 변경을 알리고 미리보기를 제공한다. 단순히 오늘 읽은 분량을 수정하는 동안에는 오늘 목표의 분모를 임의로 바꾸지 않는다.

중복 범위는 합집합으로 계산한다. 목표 밖의 범위는 오류로 안내한다. 배정이 없는 날에는 오늘 목표 없음을 표시하고, 진행률은 100%를 초과하지 않는다. 모든 계산 입력과 결과는 서버나 브라우저 저장소에 보관하지 않으며 새로 방문하면 다시 입력한다.

## 9 내보내기와 다국어 요구사항

### EXP01 Excel

- 실제 Excel 파일인 .xlsx로 내보낸다.
- 날짜, 요일, 읽기 범위, 배정 절 수, 빈 체크 칸을 제공한다. 장 수는 부분 장 여부를 식별할 수 있게 표시한다.
- 계획 이름, 시작일과 마감일, 언어, 장절 기준, 계산 기준, 생성일을 포함한다.
- Excel과 PDF는 확인과 출력용이다. 실제 완료 상태를 채우거나 앱 진도 복원용 파일로 취급하지 않는다.
- 한글과 영어, 줄바꿈, 날짜 표시가 깨지지 않아야 한다.

### EXP02 PDF와 인쇄

- 월간 달력형과 날짜별 체크리스트형을 제공한다.
- A4를 기본으로 제안하며, 영어 사용자용 Letter 지원은 후속으로 검토한다.
- 날짜별 범위와 체크할 공간을 포함한다. 긴 범위를 잘라내지 않고 줄바꿈하거나 목록형으로 배치한다.
- 계획 전체 또는 선택한 월을 내보낼 수 있다.
- 화면과 같은 계산 결과의 범위를 사용한다. 재계획 후 파일을 새로 생성할 수 있다.
- 출력 범위는 일정과 성경 참조를 기본으로 한다. 성경 전문과 AI 콘텐츠 내보내기는 각각의 사용 조건과 요구사항을 확인한 뒤 별도 확장한다.

### LOC01 한국어와 영어

- 메뉴, 날짜 선택, 오류, 상태, 내보내기 제목과 성경 책 이름을 한국어와 영어로 제공한다.
- 화면 언어, AI 입력 번역본, 장절 기준, 사용자 시간대를 별도로 관리한다. 성경 본문 전문은 화면에 표시하지 않는다. AI 설명은 한국어·영어로 제공할 수 있고, 영어 결과가 영어 성경 본문을 뜻하지 않는다는 점을 설명한다.
- AI 콘텐츠는 출력 언어별로 생성 결과를 구분한다.
- 현재 화면에서 언어를 바꿔도 입력한 계획 조건과 계산 결과는 유지한다.
- 주 시작 요일을 설정할 수 있게 하며 초기 기본값은 로케일에 따라 정한다.
- 일부 QT 제공처는 한국어 자료만 제공할 수 있음을 해당 링크에서 알린다. UI 영어 지원이 외부 원문 영어 제공을 의미하지 않는다.

## 10 데이터와 운영 원칙

### 논리적 데이터 구분

서버에는 QT 제공처, 일별 본문 범위, 성경 구조, 허용된 본문과 AI 콘텐츠를 공통 데이터로 보관한다. 개인 진도 저장용 데이터 모델과 API는 만들지 않는다.

| 개념 | 보관할 주요 정보 |
| --- | --- |
| QT 제공처 | 서비스명, 공식 URL, 날짜 기준, 사용 조건과 수집 상태 |
| QT 일별 항목 | 제공처 날짜, 본문 범위, 출처, 확인 시각 |
| 성경 구조 | 66권의 책과 장절 식별자, 기준 체계, 데이터 버전 |
| AI 콘텐츠 | 재사용 키, 상태, 내용, 근거, 모델과 정책 버전, 리비전 |
| AI 생성 작업 | 생성 키, 작업 상태, 재시도, 비용과 오류 정보 |
| 현재 계획 입력 | 화면 메모리의 범위와 기간, 요일, 제외일, 배분 방식 |
| 현재 계획 결과 | 화면 메모리의 날짜별 배정 범위와 집계 |

성경 책 이름 문자열 대신 언어와 무관한 식별자를 사용한다. 서로 다른 장절 기준의 변환은 검증된 매핑이 있을 때만 수행한다.

### SESSION01 개인 진도 비저장

- 개인 진도를 DB, localStorage, IndexedDB, sessionStorage 등 지속 저장소에 보관하지 않는다.
- 개인 진도의 자동 복원, 백업과 복원, 기기 간 동기화는 제공하지 않는다.
- 계획 입력과 계산 결과는 현재 화면의 메모리에서 처리하고 Excel 또는 PDF로 내보낸다. 새로고침이나 재방문 시 개인 계획 자동 복원은 제공하지 않는다.
- 언어 등 표시 환경 설정의 보관 여부는 개인 진도 저장과 별도로 설계한다.
- 공통 QT 콘텐츠와 AI 생성 결과의 서버 저장 및 캐싱은 유지한다.

### OPS01 장애와 품질

- QT 수집, LLM 제공자, 내보내기 작업의 장애를 브라우저의 계획 계산과 분리한다.
- AI 캐시가 사용할 수 없으면 DB의 유효한 결과를 조회한다. 모든 실패를 신규 LLM 호출로 전환하지 않는다.
- 일별 범위의 최신성, AI 생성 실패, 중복 호출, 결과 재사용률, 출력 실패를 관찰한다.
- 캐시와 프롬프트, 모델 버전 변경 이력을 남긴다.
- 운영자가 특정 제공처 연동이나 AI 콘텐츠 제공을 중단할 수 있어야 한다.

### SEC01 공개 서비스와 입력 데이터 보호

- 개인 일독 계획과 읽기 진도, QT 완료를 서버에 저장하거나 공통 AI 입력 및 일반 로그로 전송하지 않는다.
- 계획 계산과 파일 생성은 브라우저에서 처리하는 것을 기본 설계로 제안한다. 서버 처리가 필요해지면 전송 데이터와 보존 정책을 별도로 검토하고 PRD를 수정한다.
- 현재 화면의 입력 데이터를 읽을 수 있는 스크립트의 범위를 관리하며, 외부 콘텐츠와 AI 출력을 안전한 텍스트 또는 검증된 형식으로 표시한다.
- 공개 AI 요청에는 호출 제한과 예산 상한을 적용한다. 운영용 콘텐츠 수정과 중단 권한은 별도로 보호하며, 이를 이용자 회원 기능으로 노출하지 않는다.
- 외부 API 키는 서버에서 관리하며 브라우저에 전달하지 않는다.
- 제공처에서 수집한 텍스트는 자료로 취급한다. 그 안의 지시문이 LLM의 서비스 정책이나 도구 실행을 변경하지 못하게 한다.
- 같은 입력으로 반복 계산해도 결과가 일관되도록 한다. 여러 탭 사이에 개인 진도를 공유하거나 동기화하지 않는다.

### 운영 비용과 구성 원칙

- AWS와 LLM 합계가 월 10,000원 이내인지 예상 요청량, AI 생성 횟수, 저장량, 전송량을 기준으로 확인한다. AWS 서비스별 요금이나 무료 제공 구간을 확인하기 전에 예산 달성을 보장하지 않는다.
- 환율과 세금을 고려해 예산을 산정하고 AWS와 외부 LLM 사용액을 함께 확인한다. 무료 크레딧 종료 이후의 비용도 따로 검토한다.
- 공개와 학습에 필요한 최소 구성부터 시작한다. 별도 캐시 서버, 메시지 큐, 여러 실행 서비스를 필수 구성으로 미리 확정하지 않는다.
- AI 생성 횟수와 사용량을 제한하고 기존 결과를 재사용한다. 예산 여유가 부족하면 신규 AI 생성을 중단한다. 제공 가능한 기존 해설, QT 장절·공식 링크와 일독 계산은 유지한다. 구체적인 중단 기준과 사용자 안내는 실제 구성 결정 시 확정한다.
- 예산 알림과 사용량 제한을 구분한다. 월 목표 상한은 제품의 비용 제약이며 모든 서비스의 청구액을 자동으로 중단시킨다는 보장은 아니다.
- 콘텐츠 사용료와 도메인 등 추가 비용이 발생하면 포함 범위를 확인하고 출시 전 예산을 다시 검토한다.

## 12 성과 측정과 출시 순서

### 측정할 지표

| 지표 | 정의와 목적 |
| --- | --- |
| 계획 생성 완료율 | 계획 만들기 시작 세션 중 계산 또는 내보내기 완료 비율 |
| 계획 사용성 | 참여자가 자발적으로 제공한 테스트 결과로 계획 생성과 조건 변경, 내보내기 흐름을 검증 |
| AI 결과 재사용률 | AI 콘텐츠 조회 요청 중 기존 유효 결과를 사용한 비율 |
| AI 품질과 비용 | 검토된 오류 비율, 생성 실패율, 성공 콘텐츠당 호출 비용 |
| 내보내기 성공률 | 내보내기 요청 중 정상 파일 생성 비율 |

익명 이벤트 수집은 별도 정책을 정한 뒤 최소한으로 적용한다. 읽은 본문과 실제 진도를 수집하지 않으며, 기기 간 사용자를 추적하지 않는다. 장기 사용자 유지율을 계정 기반으로 측정한다고 가정하지 않는다. 성과 목표의 수치는 초기 사용 규모와 검증 데이터를 확인한 뒤 정한다. 완료율과 방문 횟수를 사용자의 신앙 수준을 평가하는 지표로 사용하지 않는다.

### 구현 순서 제안

1. 성경 장절 데이터의 출처와 사용 조건을 확인하고, 66권 범위 계산 구조를 만든다.
2. 일독 계획 생성과 재계산, 현재 읽은 분량 입력과 진행률 차트, 캘린더, Excel과 PDF를 구현한다.
3. 권한이 확인된 QT 제공처의 오늘 장절 범위와 공식 링크를 연동한다. 본문 전문은 사이트 안에 표시하지 않는다.
4. WEB 본문과 QT 범위의 절 대응 및 이용 조건이 확인된 경우 AI 요약과 설명, 생성 작업, 결과 재사용, 오류 수정 기능을 구현한다.
5. 한국어와 영어 전반, 개인 진도 비저장, 공개 AI 호출 제한, 장애 상황, 출력물과 콘텐츠 품질을 검수한다.

AI는 출시 범위에 포함하되, 본문 사용 조건과 품질 검토가 준비되지 않으면 해당 기능의 공개를 보류한다. 전체 출시 일정과 인력은 아직 정하지 않는다.
