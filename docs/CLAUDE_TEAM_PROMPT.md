# Claude Sonnet 5 에이전트 팀 시작 프롬프트

이 문서는 Claude Code의 Agent Teams 기능을 사용하는 경우의 인계 프롬프트다. [구현 인계 계획](IMPLEMENTATION_PLAN.md)과 [PRD](PRD.md)를 함께 읽혀야 한다. 팀 기능은 대화형 Claude Code에서 활성화해야 한다. Anthropic의 [Agent Teams 공식 문서](https://code.claude.com/docs/en/agent-teams)는 환경 변수로 기능을 켜고 자연어로 팀원 역할을 지정하는 방식을 안내한다.

Claude Code를 이 저장소에서 시작할 때의 예시:

~~~sh
CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 claude --model claude-sonnet-5
~~~

에이전트 팀은 비대화형 claude -p에서 생성되지 않는다. 실행 환경에서 claude-sonnet-5를 사용할 수 있는지 확인하고, 사용 불가능하면 다른 모델로 조용히 대체하지 말고 사용자에게 알려라. 모델과 팀 기능의 현재 지원 여부는 시작 시 공식 문서와 로컬 Claude Code 버전에서 확인한다.

아래 프롬프트를 대화형 Claude Code에 붙여 넣는다.

~~~text
이 저장소의 말씀하루 프로젝트를 구현해 줘. 먼저 git status를 확인하고 README.md, docs/PRD.md, docs/IMPLEMENTATION_PLAN.md, docs/CLAUDE_TEAM_PROMPT.md를 전부 읽어라. PRD가 제품 요구사항의 기준이고 IMPLEMENTATION_PLAN.md의 M0~M7이 실행 순서다. 현재 구현 코드는 없으며 README와 PRD에는 기존 스테이징과 이후 수정이 함께 있으니 보존하라.

이번 작업은 일반 subagent 위임이 아니라 Claude Code Agent Team으로 운영하라. 너는 team lead이고, 팀원도 모두 claude-sonnet-5를 사용하라. 팀이 실제로 생성됐는지 확인한 뒤 공유 작업 목록을 만들고, 각 작업에 담당자·의존성·소유 파일·완료 기준을 지정하라. 팀원의 대화 내역이 너에게 자동으로 전달된다고 가정하지 말고 아래 문서와 담당 범위를 각 팀원의 시작 지시에 포함하라.

초기 팀원 다섯 명을 다음 이름과 책임으로 구성하라.

1. source-rights: 공식 사이트와 데이터 출처 조사 담당. docs/data-sources.md와 docs/rights-matrix.md만 소유한다. 66권 장절 구조 데이터, 매일성경·생명의삶의 오늘 장절 취득 경로, 공식 링크, 본문 웹 표시·보관·AI 입력·AI 출력 저장 조건을 각각 근거 URL과 확인일로 기록한다. 365QT는 조사만 하고 첫 출시 범위를 바꾸지 않는다. 외부 권리자에게 실제 메시지를 보내지 말고 문의 초안까지만 준비한다. 코드와 PRD는 수정하지 않는다.

2. qt-backend: services/qt/**만 소유한다. 제공처별 어댑터, 날짜·장절 정규화, 공식 링크, 상태 모델, 로컬 API 계약 검증을 구현한다. 공개 허가 전에는 권한 미확인 성경 본문이나 제공처 해설을 저장·공개하지 않는다. 장절을 못 얻으면 공식 링크만 반환하고 어제 자료를 오늘로 대체하지 않는다. 매일성경의 동적 로딩과 생명의삶의 EUC-KR 응답을 조사해 실패 상황까지 검증한다. API 계약 초안을 lead에게 메시지로 보내고, 중앙 계약 파일은 lead가 작성하게 한다.

3. planner-core: web/src/domain/**, web/src/data/**와 그 영역의 테스트만 소유한다. 66권 데이터 버전, bookId, 목표·읽은 범위의 합집합, 장 수/절 수 배분, 날짜·요일·제외일, 재계산, 진행률의 순수 계산 로직을 만든다. source-rights가 데이터 출처를 확정하기 전에는 만든 작은 테스트 데이터만 사용한다. 날짜별 배정의 합집합이 목표 미독 범위와 같고 중복이 없는지 검증한다. 개인 입력을 저장소나 서버로 보내지 않는다.

4. web-experience: web/src/app/**, web/src/components/**, web/src/export/**, web/src/i18n/**, web/src/styles/**만 소유한다. 오늘 QT 카드, 공식 링크 대체 화면, 계획 입력, 목록·캘린더·진행률, 실제 .xlsx/PDF, 한국어·영어 UI를 구현한다. planner-core의 계산 함수를 재구현하지 않는다. QT API와 계획 결과 계약이 확정되기 전에는 별도 mock으로 화면을 만들고, 계약을 lead와 합의한 뒤 연결한다. 브라우저 지속 저장소에 개인 진도를 쓰지 않는다.

5. platform-cost: infra/**, .github/workflows/**, docs/cost-estimate.md만 소유한다. AWS 리전별 정적 호스팅·API Gateway·Lambda·저장소·스케줄·로그·전송량 및 LLM 비용의 낮음/기준/증가 시나리오를 만든다. 현재 공식 가격과 크레딧 종료 후 비용을 확인하고, 서버리스 IaC와 CI를 준비한다. 실제 AWS 계정 배포나 유료 리소스 생성은 비용표와 IaC 변경 내역을 lead가 사용자에게 제시해 진행 지시를 받은 뒤 실행한다.

team lead인 너는 초기 저장소 골격, 공통 빌드 파일과 의존성 버전, docs/contracts/**, README.md, docs/PRD.md, docs/IMPLEMENTATION_PLAN.md를 전담하라. 팀원과 같은 파일을 동시에 수정하지 마라. 초기에는 QT 응답 계약과 계획 결과 계약을 먼저 정하고 담당 팀원 모두에게 전달하라. 팀원이 소유 범위 밖 파일을 바꿔야 하면 메시지로 합의한 뒤 소유권을 잠시 이전하라. 팀원 작업이 끝났다고만 보고하지 말고 변경 사항과 테스트를 직접 확인하고 통합하라.

작업 순서와 병렬 처리:
- M0의 자료·권한·비용 조사와 M1의 QT 기술 실험은 동시에 진행한다. planner-core는 테스트 데이터로 계산 엔진을 시작할 수 있고, web-experience는 합의된 mock 계약으로 화면을 시작할 수 있다.
- source-rights의 데이터 출처 결정 전에는 실제 66권 데이터를 확정하지 않는다. QT의 범위 취득 허용 여부가 미정이어도 공식 링크 대체 화면과 일독 계산은 계속 구현한다.
- M2 계산 계약이 안정되면 web-experience가 M3 화면·내보내기를 연결한다. M4는 비용표가 통과한 뒤 배포한다.
- 본문과 AI 사용 조건이 확인되면 새로운 ai-content 팀원을 생성해 services/ai/**를 맡긴다. 이 팀원은 캐시 키, 동일 키의 단일 활성 생성, 예산 차단, 검토·리비전·오류 신고를 구현한다. 조건이 확인되지 않으면 AI 공개를 보류하고 링크 중심 제품을 계속 진행한다.
- QT와 AI의 계약이 생기면 새로운 msa-lab 팀원을 생성해 labs/spring-cloud/**를 맡긴다. Gateway, Config, Eureka, CircuitBreaker를 로컬에서 실습하고 AI 중단 시 QT 링크가 유지됨을 검증한다. 실제 AI 자료 권한이 없으면 모의 AI 응답을 사용한다. 이 학습 트랙 때문에 첫 공개를 지연하지 않는다.
- 각 주요 단계의 통합 시점에는 독립적인 qa-review 팀원을 생성한다. 이 팀원은 처음에는 읽기 전용으로 PRD의 해당 AC, 개인정보 비저장, QT 날짜·링크, 출력 일치성, 장애 대체 흐름을 검토하고 docs/qa/**에 재현 가능한 결과를 남긴다. 제품 코드 수정은 lead가 재배정한 뒤에만 한다.

모든 팀원이 지킬 규칙:
- 공통 작업 목록에서 의존 작업이 끝난 과제만 시작한다. 한 과제는 한 팀원이 소유한다. 서로의 진행 상황과 계약 변경은 직접 메시지로 공유한다.
- 제공처 페이지가 공개돼 있다는 사실만으로 본문·해설의 재게시나 AI 입력 권한이 있다고 판단하지 않는다. 허용된 정확한 본문 데이터가 없으면 AI를 생성하지 않는다.
- QT 열람을 일독 배정이나 진도에 반영하지 않는다. 개인 계획과 읽은 범위는 서버·브라우저 저장소·일반 로그·분석 이벤트에 남기지 않는다.
- 구현한 기능마다 해당 PRD 검수 기준을 지정하고 의미 있는 테스트로 확인한다. 화면, Excel, PDF는 같은 계획 데이터를 사용한다.
- 기존 변경을 되돌리거나 다른 팀원 파일을 덮어쓰지 않는다. 브랜치·커밋·스테이징도 lead가 일관되게 관리한다.
- 팀원이 완료를 알리면 lead는 파일 변경, 테스트 결과, 미해결 문제를 확인한 뒤 공유 작업 목록의 상태를 갱신한다. 모든 의존 팀원이 끝나기 전에 통합 완료를 선언하지 않는다.
- 작업이 권한 확인이나 계정 접근 때문에 막히면 그 과제의 근거와 대체 경로를 기록하고 다른 독립 과제를 계속 진행한다. 나의 추가 지시가 필요한 실제 외부 연락, 유료 배포, 공개 범위 변경은 구체적인 준비 결과를 먼저 제시한다.

지금 즉시 M0·M1의 공유 과제를 만들고 다섯 팀원을 생성하라. 가장 먼저 두 QT 제공처의 오늘 날짜·장절·공식 링크를 공통 모델로 검증하는 로컬 수직 기능을 완성하라. 이후 M2~M7을 의존 순서대로 계속 진행하라. 각 단계가 끝나면 완료 항목, 담당자별 변경 파일, 실행한 검증과 결과, 권한·비용 미확정 항목, 다음 단계를 간결하게 보고하라.
~~~

Agent Teams가 중간에 종료되거나 세션을 다시 열면 기존 팀원이 자동으로 복구된다고 가정하지 않는다. 새 세션의 lead가 git 상태와 계획 체크박스를 확인하고 필요한 팀원을 다시 생성해 이어간다. 팀 구성과 모델 선택은 [Agent Teams](https://code.claude.com/docs/en/agent-teams) 및 [Claude Code 모델 설정](https://code.claude.com/docs/en/model-config) 문서의 현재 동작을 기준으로 확인한다.
