# UI 탭·오늘 QT 검수 기록

- 검수일: 2026-09-26
- 범위: `오늘의 QT` / `일독 계획` 탭 분리, 상태 유지, 디자인 반영, QT 장절 미표시 원인
- 방식: 자동 테스트·빌드, 로컬 데스크톱 브라우저 확인, 별도 QA 에이전트의 읽기 전용 검토

## 결과 요약

- 두 패널은 기본 `오늘의 QT` 탭으로 열리고 탭 전환 시 선택된 패널만 접근성 트리에 표시된다. 일독 계획 컴포넌트를 계속 마운트해 입력 상태를 보존한다.
- 키보드 탐색, 탭 패널 계약, 한/영 문구, QT 탭 복귀 시 서울 날짜 재확인을 포함한 웹 전체 회귀가 통과했다.
- 참고 앱의 차분한 배경, 흰 카드, 둥근 모서리, 인디고 선택 상태를 적용했다. 데스크톱에서 QT 카드 두 개가 나란히 보이고 일독 계획 입력·결과는 별도 탭 안에 표시되는 것을 확인했다.
- QT 범위가 기본 화면에서 아직 표시되지 않는 것은 어댑터 오류가 아니다. 기본 `qt.acquisition.enabled=false` 설정이 의도적으로 제공처 요청을 막아 `RANGE_NOT_PERMITTED` / `PERMISSION_UNCONFIRMED`와 공식 링크만 반환한다. 실제 제공처 접근 허용 여부가 확인되지 않아 실취득은 실행하지 않았다.

## 미확인·후속

- 모바일 뷰포트와 다크모드 실기 확인은 하지 않았다.
- 인쇄 미리보기는 열지 않았다. CSS에서 활성 계획 패널만 인쇄하고 숨겨진 패널을 제외하도록 처리했으나 브라우저 인쇄 결과는 미확인이다.
- 키보드 동작은 자동 테스트로 확인했으며 별도 스크린리더 실기는 하지 않았다.
- `dev:qt:live` 프로필은 실요청을 수행하지만 이번에는 실행하지 않았다. 사용자가 로컬 실취득을 선택하면 외부 요청을 하기 직전 범위와 위험을 다시 확인하고 별도 점검한다.
- 따라서 두 탭 UI는 검수됐으나 “오늘 QT 장절이 실제로 화면에 나온다”는 동작은 아직 승인·실취득 확인 전이다. 기본값을 임의로 켜지 않는다.
